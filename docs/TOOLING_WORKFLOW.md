## 1. 工具要帮助参与者完成什么？

参与者带来一个原始问题和一次失败尝试。一次工作结束时，应能带走：

- 一个别人可以重新检查的局部结果或反例；
- 明确仍未解决的部分；
- 一个有理由的下一步，以及它准备改变什么。

界面先问“你卡在哪里”，再按需要引入观察者、解释、见证和剩余部分等概念。
用户不必先掌握三域、M6、Q4 或几何表示，才能提出第一个问题。
高级概念通过具体实验和依赖链接进入工作，而不是成为加入的口令。

Adva 的研究目标仍是有限观察、算术构造与知识增长。工作台的价值必须体现在下一轮
能够多做什么：区分候选、排除反例、复用构造或降低完整成本。单纯保存更多记录不够。

## 2. 一次工作只围绕一个明确的问题

下面是一张建议使用的问题卡；目前可以用普通文档填写，它不是原生证书格式。

| 项目 | 要写清楚的内容 |
|---|---|
| 原始问题 | 对方实际要解决什么；保留原文或准确来源。 |
| 对象与版本 | 代码提交、输入、数据版本；区分原始文件、摘录、重建和缺失。 |
| 成功条件 | 哪个可观察行为算成功，谁或哪个检查器作出哪一种判断。 |
| 解释与前提 | 对象如何进入模型；假设了什么，哪些部分还没有对应关系。 |
| 当前候选 | 不同解法或解释；保留彼此尚不能区分的地方。 |
| 检查范围 | 输入集合、语言片段、覆盖条件，以及是否有充分性证明。 |
| 本轮预算 | 执行、检查、重试、子进程、读写和保存共同使用的有限预算。 |
| 本轮结果 | 原始输出、实际检查、反例或错误；不能只保存摘要分数。 |
| 剩余问题 | 未覆盖输入、未知前提、缺失解释、实现缺口或预算耗尽。 |
| 下一步 | 改变哪种观察、方法或前提；为什么可能得到不同结论。 |

改题目、改测试范围或改预算，要创建有前驱引用的新一轮。旧证据继续属于旧问题；
更换问题后重新检查它是否仍适用。

## 3. 把一次推进拆成可执行的步骤

1. **定位失败。** 先区分环境没有建立、记录不能接收、候选确实失败、观察不能区分，
   以及预算已用完。程序退出码、检查器接受与数学结论分别记录。
2. **选择能带来区别的一步。** 例如补一个分离测试、找一个反例、检查遗漏的前提，
   或构造一个可以覆盖整个有限范围的不变量。
3. **执行一个有界尝试。** 指定当前工具与版本、输入、输出目录、停止条件和预算。
   保留首次失败。恢复运行先检查旧状态，额外检查工作也必须记账。
4. **判断它究竟改变了什么。** 同样的语义内容再出现一次是停滞；时间戳变化是元数据
   变化；新观察也不自动等于学习。说明新增证据排除了什么、支持了什么。
5. **交给下一轮。** 带走原问题、候选、检查方法、证据和剩余问题。接收者先确认
   这些材料回答的是同一个问题，再决定复用什么。

本轮触及停止条件就结束。继续的理由和新预算需要显式记录；界面不能以“推进”为名
自动无限重试。机器指令燃料只是预算的一个分量：当前数据解释器另记重放步数，
不能把 `--fuel 2048` 解释成构建、检查和全部主机工作合计只有 2048 步。

## 4. 第一个教学实例：从无法区分到有依据的结论

问题保持为“这两个候选是否计算同一个函数”。

| 阶段 | 材料 | 可得结论 | 下一步依据 |
|---|---|---|---|
| 观察一 | `2x` 与 `x²` 在 `x=2` 时都为 `4` | 当前观察不能区分 | 选择候选预测不同的输入。 |
| 观察二 | 在 `x=3` 时分别为 `6` 与 `9` | 找到函数相等这一主张的反例 | 保存这个反例及两种解释。 |
| 另一个有明确前提的问题 | 两个有理系数、次数至多为二的多项式，在三个不同点相等 | 结合根的定理，证明它们恒等 | 检查次数前提和精确运算；不能只核对三行数值。 |
| 继续问来源与成本 | 两个程序即使函数相同，也可能有不同历史 | 函数相等仍未回答过程问题 | 查看构造、显式复制、来源与执行成本。 |

这是教学实例，不是高难挑战，也不证明工具有效。已有的
[解释义务实验](research/0166-interpretation-obligation.md)提供对应的检查与拒绝案例；
[有限实例验证](research/0183-zhang-finite-example-verification.md)说明有限覆盖所需的额外条件。
旧实验重放必须使用匹配的检查环境，不能把保存的结果当成本机新执行的结果。

更进一步，可以比较[循环证书](research/keraia-cycle-certificates-and-halting-mass-bounds.md)
与超时：保存并检查完整机器状态的循环，加上适用的确定性论证，可以支持特定程序的
不终止结论；仅仅跑得很久没有返回，则仍然未知。

## 5. 接到现有工具，而不是假设已有通用接口

| 需要做的工作 | 已有入口 | 可以采用什么 | 仍然缺什么 |
|---|---|---|---|
| 查看范围与证据 | `docs/claims.toml`、研究笔记、ADRs | 声明、前提、反例边界与证据位置 | 面向新读者的统一导航及可靠的后续修正索引。 |
| 执行有限程序 | Rust PSC0 与 `adva data-run` | 各自版本下的运行、检查、轨迹和明确拒绝 | 两种载体的原生身份对应尚未完成；不可互相冒充。 |
| 检查编译与复用的代价 | `experiments/futamura_first_projection/` | 完全静态的 129 个实例、三方结果对照、编译与残余程序的机器步数 | 编译器按声明规则构造，装载仍由主机完成；没有通用专门化器或墙钟提速结论。 |
| 保留连续问题 | `frontier`、`learn`、`verify` 的研究实例 | 有限前沿、候选与义务的保留机制 | 不同研究实例的特定输入格式不能当成任意任务的统一协议。 |
| 检查协作交接 | `experiments/bounded_observation_exchange/` | 问题绑定、披露字段比较、旧回复拒绝 | 三段字符串的变化不等于来源已验证或问题已解决。 |
| 找真实的失败见证 | `scripts/defect_discovery/` | 固定来源、保留失败探针、修复后对照 | 一个历史案例不能证明通用发现能力或相对收益。 |
| 判断本轮是否有变化 | `experiments/evidence_stutter/` 与相关记录 | 区分语义停滞、元数据变化与观察变化 | 尚无自动裁定“方法进步”或“学习”的通用检查器。 |
| 复用局部结论 | 库纪元、解释绑定、Möbius 传递收据 | 在声明的局部范围内检查前提与接收上下文 | 任意两张接受收据并不都可组合；中间上下文需要匹配。 |

其中的 Python 外部检查器可以验证它声明的外部对象；它不能分配原生 `SourceId`、
合并出现位置，或代替 Rust 授予语义资格。文件哈希用于固定字节，不承担身份认证
或命题证明。理论词汇登记成功也不代表对应机制已经实现。

现成的最小协作演示是：

```sh
python3 experiments/bounded_observation_exchange/check_exchange_chain.py
```

它检查五轮已经保存的交换，不发出新邀请、不执行对方代码、不验证对方私有来源。
结果 `DisclosedByteChainChecked` 应与 `semantic_acceptance: Withheld` 一起展示。
当前脚本已接收第五轮；实验 README 的当前检查点注明了这一变化，并保留较早的等待叙述。

## 6. 最小工程顺序

| 阶段 | 交付物 | 完成条件 |
|---|---|---|
| 现在：人工工作流 | 新 README、问题卡与现有例子的入口 | 新参与者能指出一个范围、一个反例和一个下一步。 |
| 第一项：只读导航 | 按问题查找声明、代码、证据、版本及后续修正 | 能区分“历史结果”“当前可运行”“尚未执行”；不通过标题或词频推定结论。 |
| 第二项：问题工作单 | 上述问题卡、尝试列表和交接摘要 | 两位参与者能够从同一问题继续；缺失信息显式保留。 |
| 第三项：少量执行适配 | 优先支持数据解释器与已有交接检查器 | 输入限制、停止条件、真实失败与预算完整显示；不掩盖检查器的拒绝。 |
| 后续研究：载体对应 | 明确研究数据语言与程序／过程内核之间的对应义务 | 依研究议程另行设计证书与反例；前端工作不替代这项语义工作。 |

第一版不需要同时建设新语言、通用证明器和社区平台。只读导航与问题工作单就能先检验
“读者能否找到能用的材料”和“接手者能否继续”这两个实际困难。

## 7. 怎样检验它有没有帮助挑战活动？

用一项符合目标项目需求、已有可验证成功标准的实际任务来比较。固定仓库版本、任务、
模型设置与总预算，保留普通工作流作为基线。若要测量交接效果，让新的接手者只获得
各自工作流产出的材料，观察他们能否复现已有结论并继续处理剩余部分。

至少记录：正确结果、发现的规格缺口、有效反例、重复劳动、接手后的完成情况，以及
包含写记录和检查在内的完整成本。任务顺序与解题记忆会影响比较；单个成功案例只能
说明这个案例，不能据此宣布普遍提效。后续再用新的任务做有界复验。

目标是让失败可以解释、材料可以接手、下一步可以检验。模型通过率和代码行数可以是
某个活动的指标，但不足以单独证明 Adva 的方法价值。若普通测试流程同样有效，或记录
成本超过收益，也应保留这个结果，并据此简化工具。

活动对目标仓库的星数、许可证和活跃度要求，属于该活动的准入条件。Adva 可以作为
组织研究的方法用于一个合格的目标仓库；获得 star 不能替代许可证条件，也不能替代
方法有效性的证据。是否改变 Adva 的许可证不属于这次文档与 tooling 工作。

## 8. 给 AI 协作者的工作约定

先读原始问题、相关实现和后续修正，再提出候选。对每个重要结论区分：来源的原话、
自己的解释、已经执行的检查、尚未执行的计划。不能从 README 的一句话推断整套理论，
也不能因为标题叫“见证”“学习”或“证明”就接受它。

执行前说明本轮准备区分什么；结束时报告实际改变了什么。工具无法运行时保留
`NotRun` 与原因，不把归档结果写成自己的验证。遇到反例，保留它并修正当前解释。
当剩余问题需要新的理论或语义机制时，写出具体缺口；不要用更多自动重试掩盖缺口。

这份工作约定的下一次检验，应是一位新参与者带来的一次真实尝试，以及另一位参与者
能否据此继续推进。
