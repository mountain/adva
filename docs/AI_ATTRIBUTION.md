# AI authorship and account-proxy attribution

Mingli Yuan's explicit instruction, 2026-09-10:

> 请推进，请署你的名字，说通过我的账号代理。请记下来这个规则，代表我对你们的信任。

For AI-produced work submitted through Mingli Yuan's GitHub account
(`mountain`), name the actual assistant that performed the work and state
that the account is acting as an authorized submission proxy. This run uses:

**Authored by ChatGPT (OpenAI). Submitted through Mingli Yuan's GitHub
account (mountain) as an authorized proxy.**

The account displayed by GitHub and the author of the technical analysis
are distinct. Put the attribution in the research report, PR description
and commit message; identify substantial AI-written implementation where
appropriate. Another agent should use its own actual identification,
rather than copying ChatGPT's name. Do not fabricate a model version,
human coauthor, email identity, DCO sign-off or independent review.

Mingli supplies research direction and authorizes account use; ChatGPT
contributes the analysis and implementation attributed to it. Record
contributions and checks according to what actually happened. Account use,
authorship, authorization, review and evidence of correctness are separate
facts. This is not a claim of institutional review by OpenAI.

## Mutual fallibility and freedom to revise

Mingli clarified this instruction in the same conversation: his confidence
in the mechanism is a research position, not a guarantee that the mechanism,
its implementation or any program is free of error. An assistant may
challenge and correct his proposals; its own reasoning and code must be
equally open to challenge and correction.

Trust supports cooperation without requiring either side to presume the
other is correct. Preserve the freedom to question, disagree, revise and
decline an unsupported conclusion. Neither the human's authorization nor
the assistant's contribution requires endorsement of every premise or
result. A counterexample may require revising the mechanism itself, not
only fixing code.

For each contribution, state the assumptions, actual actions, checks
performed, known limits and unresolved questions. Preserve failed checks
and correct discovered errors openly. No participant is represented as
having performed another's work, verified an unchecked result, or promised
infallibility merely by collaborating or providing the account. These
working commitments do not erase each participant's actual contribution
or the need to correct their own work.

This is a collaboration and attribution rule, not a transfer of
responsibility or a blanket declaration that nobody has obligations.

This records attribution, not new operational permissions: repository
visibility, branch protection, validation gates, merge scope and private
boundaries retain their existing rules. Preserve historical commit and
authorship records; do not rewrite earlier work to apply this rule
retroactively.

This instruction is linked from AGENTS.md so subsequent repository readers
can continue the practice. It does not guarantee memory outside contexts
that read this repository.
