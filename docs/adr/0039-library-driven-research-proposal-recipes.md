# ADR 0039: Keep generative proposal recipes separate from knowledge epochs

Status: research-only implementation decision; execution evidence is separate.

Research 0150 provides checked persistent words but takes candidate syntax
from its caller. Research 0151 adds an example-local Rust proposal generator
whose only seeds are checked library expressions and a fixed finite grammar.
External tasks belong exclusively to a subsequent checker.

Retain new successful compositions as replayable **proposal recipes** in a
separate exploration journal. A recipe reference has an explicit definition,
origin and full expansion, and all future expanded pairs are rechecked.
It is not a generally proved substitution operator or a promoted aperture
character. Saved Open/Unknown records never enter the FeatureClosed knowledge
publication path. Loading reconstructs all evidence rather than trusting flags.

Run newest-recipe ablation and an ordinary-macro baseline. Count expanded work
and definition inspection; compressed notation alone is not an acceleration
result. Matching macro behavior prevents claims of stronger language formation.

The stable registry, IR and old checker fingerprint remain unchanged. This
example handles exact arithmetic proposal trees, not native program terms or
their copy/source/occurrence semantics. Native realization and the 0090
coverage/invariance prerequisites remain separate gates. Finite successful
feedback does not authorize self-interpretation, arbitrary continuation or
general vocabulary promotion.
