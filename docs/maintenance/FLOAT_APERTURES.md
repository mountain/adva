# 浮点与主机不确定性引入的开口（float and host apertures）

日期：2026-09-12。执行：deepseek-v4-flash-vision-exp（DeepSeek Harness），经 Mingli Yuan 的
账号代理提交。扫描器：[`scripts/float_aperture_scan.py`](../../scripts/float_aperture_scan.py)；
机器可读结果：[`float-apertures.json`](float-apertures.json)。

缘起：苑明理的观察——**每次跑验证、分析和运算，都有可能因数值不精确而重新引入一个新的
开口**；而**看得见的那些开口或误差，本身有结构**。这份清单把"可能在哪里开"与"开成什么
形状"分开列出来，先列，不先修。

## 0. 边界

这份清单**不做**以下事：不裁定某个实验是否因此失效；不改任何检查器；不声称浮点误差是
随机的（见 §3.1，恰恰相反）；也不把"含浮点构造"等同于"判定不可靠"。它给出的是**入口与
形状**，以及一条可重复执行的扫描。

## 0.1 复扫（同日，仍未修任何检查器）

本清单首次记录时扫到 **69** 个实验、声明免浮点 **7** 条（其中 6 条成立）。在同一日的后续
推进里又加入两个精确实验（`aeg_core_shell_symbolic`、`aeg_core_shell_multivariate`，判定均为
`exact-only`），于是本次复扫为 **72** 个实验、声明 **10** 条（9 条成立），`host` 类升到
60 个（新增的一个读钟）、`drift` 类仍是 28 个——**新增的两个实验一个开口都没带来，那是因为它们本来就精确，
不是因为我修了什么**。原先"69 个里只有 14 组可比"的预算比对没有重跑，所以它仍按 69 的口径读。

数字会随实验增加而移动，所以**这份清单的读法是"某一时刻的入口与形状"，不是"当前的精确
计数"**；`float-apertures.json` 每次复扫都整体重写，历史数字只留在这一节里。

**第七次复扫（同日，0196）**：`protocol_declaration` 判为 **`exact-only`**（该类别 7 → 8）——
**一个只做判定的检查器**，没有墙钟、没有浮点：平方根与除法取整都用整数。这是这条
"把协议写成声明"的路线第一次把**判定**本身也做成精确的。

**第六次复扫（同日，0195）**：`joined_chain_cost` 判为 `imprecision-in-illustration-only`
（两处墙钟；取整一律用整数）。这一轮**没有**引入浮点判定：深度天花板用**整数平方根**，
代价的取整用 `-(-a // b)` ✓。

**第五次复扫（同日，0194）**：`measured_join_cost` 是**测量**一轮，判为
`imprecision-in-illustration-only`：四处 `host`（两条命令的两次墙钟）与两处 `binary64`
（同两处计时取整），**都不在验收路径上**。但这一轮里**真正该记的浮点开口是我自己写进去的**：
深度天花板一度写成 `pool ** 0.5` ✗，**已换成整数平方根**；也就是说，**一个以"该测不该声明"
为宗旨的运行，自己差点把判定建在 binary64 上**——这正好说明扫描器抓的是"类型"，不是"意图"。

**第四次复扫（同日，0193）**：`traversal_allocation_optimal` 复算"最优份额"，
**全是有理数**，只因记录了**声明的墙钟耗时**落在 `imprecision-in-illustration-only`——
与 0191 同一原因（那一格 `host` 就是读钟，不在验收路径上）。同一轮真正踩到的坑**不是浮点**，
而是**搜索规模失控**（让穷举跑到准备金推得动的天花板）把断言预算击穿：**量纲/规模错不会
被浮点扫描器抓到**，只能靠预算上限与互证拦下。

**第三次复扫（同日，0192）**：`traversal_allocation_and_reserve` 被**正确**判为
`imprecision-can-decide`——它有**两行浮点比较在验收路径上**（"0.33×3+0.01 是否等于 1.0"、
"三分之三是否等于 1.0"）。这两行是**探针**：它们要测的正是 binary64 在这件事上做什么，而
**真正的断言在精确有理数那边**（偏差非零、为负）。所以这条判定我不修正，只登记：**若换一个
不遵守 IEEE-754 舍入的算术，探针会响亮地失败，而精确断言仍然成立**。同一轮里另有一处
**单位混用**（步数加分数）是精确算术**没有**拦住的——精确 ≠ 量纲正确。

**第二次复扫（同日，0191）**：`read_boundary_mass_halves` 是**精度上精确**的一轮（只有
有理数），但它在证据里记了一个**声明的墙钟耗时**用于预算记账，于是被判为
`imprecision-in-illustration-only`——**那一个 `host` 计数就是那次读钟**，它不在任何验收路径上，
而且是冻结对比里**唯一**被排除的字段。把它记在这里，而不是为了好看删掉一个资源测量。

## 1. 四个进入类别（必须先分开，混在一起正是本清单要抓的错）

| 类别 | 是什么 | 是否精确 |
|---|---|---|
| `binary64` | 真正的 IEEE 双精度：`float()`、`math.sqrt/log/exp/...`、`cmath`、`numpy`、`round()`、`"%.Nf"` | 否，带舍入 |
| `intmath` | `math.gcd/isqrt/comb/factorial/lcm`、`Fraction`、`Decimal` | **是**，精确 |
| `host` | `perf_counter`、`time.monotonic`、`getrusage`、峰值 RSS | 不是精度问题：**逐次运行本就不同** |
| `drift` | 未定种子的 `random`、依赖哈希随机化的集合/字典遍历序、读环境变量 | 同上，另一条来源 |

**扫描器第一版就把 `math.gcd` 报成了浮点**——那是整数运算。这类"名字像浮点、其实是精确"
的误报，与本仓库反复出现的那类错误同族（量不是它名字所说的量），所以类别必须分开写。

## 2. 入口清单（每条带本仓库的实例）

### 2.1 精确算术**内部**的浮点泄漏

实例（我自己犯的）：`experiments/integer_power_absurdity/calibration.py` 的向外取整
`(lo * scale).__floor__() / scale` —— Python 3 的 `/` 是真除法，返回 float，于是声明的
`10^-45` 网格实际只有 double 精度（约 1e-16）。**声明精度与实际精度之间的落差就是开口**，
而它只能靠**测量区间宽度**发现，不能靠声明。教训已记在 0172 号笔记 §8 第 3 条。

### 2.2 显示精度 ≠ 实际精度

同一个文件里，`float(Fraction)` 打印 30 位数字时，**第 17 位之后是确定的、但无意义的尾数**
（二进制表示的精确展开）。它看起来像"更精确"，实际不是，而且它**可复现**——所以容易被当成
证据。形状上：有效位与装饰位之间没有标记。

### 2.3 墙钟时间判定"是否在预算内"

扫描到的最普遍机制。本仓库 **64 / 77** 个实验含 `host` 类构造，其中大多数是这种形状：

```python
"within_time_budget": (time.monotonic() - started) <= CONTRACT["budget"]["wall_seconds"]
```

实例：`hns_wall_localization/calibration.py:527`、`feigenbaum_fixed_point/calibration.py:316`、
`borromean_longitude_audit/check.py:36`、`disclosure_binding/calibration.py:43`、
`frame_covariance/run.py:20`（硬编码 9 秒）等。

**形状**：被约束的东西自己度量约束——一次运行是否"在预算内"，是一个**采样**事实，不是
性质。它的翻车概率有一个**可测的速率**：实际耗时 / 声明预算。

### 2.4 计时与内存被写进证据

证据里出现的非确定字段（计数取自 `experiments/**/*.json`）：`wall_seconds` 出现在
**119** 个文件、`cpu_seconds` 57、`validation_seconds` 45、`peak_rss_kib` 25。
后果：**逐字节重放对这些文件在结构上不可能**。实例：ChatGPT 的 sharkovsky 两条证据
`attempt-01.json` 与 `replay-01.json` 的差异只有 5 处，其中 3 处正是耗时与峰值 RSS，
数学见证完全一致（我独立比对过）。

### 2.5 取消误差聚集在判别式零点

实例：`experiments/density_wave_marginal_wall/` 里 `min f = κ²(1 − Q⁻²)`，当 `Q → 1`
（临界墙）时两侧相减 → 相对误差 ∝ 1/到墙的距离。**误差不是均匀铺开的噪声，它贴在墙上。**

### 2.6 平局处的离散翻转

实例：`experiments/hns_*` 的墙是**斜率相等**（哪个子对象"最大"的平局）。浮点噪声在这里
改变的不是量值，而是**结构本身**——滤过变了，而同构类集合没变。

### 2.7 绝对网格在大数量级上整体失效

实例：`integer_power_absurdity` 的 `10^-45` 绝对网格在模长 `8×10^13` 的分支上宽度超过一个
单位，整数性**根本不可判定**；修法是折半平方把精度变成**相对**的。形状：不是误差变大，而是
**判定整体无效**，此时唯一诚实的输出是 `Unknown`。

### 2.8 同一量的两条路径不等

`min f` 可由 `−Δ/(4c_s²)` 或 `κ²(Q²−1)/Q²` 算出；只有在精确算术下两者才**逐位相等**。
形状：浮点破坏的是**路径无关性**这个不变量，而不是某个数值。

### 2.9 迭代、网格极值与伪周期

迭代映射的误差按 Lyapunov 指数增长，"近似周期"可能被读成**精确周期**（新的开口：一个
精确性声明）。同类：在网格上取 `argmax`/`min` 时，极值点在平局附近翻转。
（`feigenbaum_*` 五个实验是本仓库 `binary64` 使用的榜首，其对象本身是超越常数。）

### 2.10 未定种子与环境

本仓库 **28 / 77** 个实验含 `drift` 类构造：未定种子的 `random`、依赖哈希随机化的集合
遍历序、读环境变量。形状与 `host` 相同，只是来源不同。

## 3. 误差内部的结构（本清单的重点）

1. **浮点误差不是随机的，它是确定的。** 同样的表达式、同样的 libm、同样的指令集 → 逐位
   相同。所以"总有一定概率"应更准确地读作：**存在许多等价的算法变体（求和顺序、是否 FMA
   收缩、SIMD 宽度、x87 与 SSE、宿主快慢），我们没有声明跑的是哪一个**。开口是**声明与执行
   之间的缝隙**，不是掷骰子。
2. **相对误差地板（~1e-16）**：任何用 double 的路径都有这个地板。它与"声明精度"之间的
   落差，就是 §2.1 那种开口。
3. **放大因子有形状**：取消 → 1/到墙距离；求和 → 与项数成比例的漂移；迭代 → 指数增长。
   三条都是**可以在运行前估出来的**，只是我们从没声明过。
4. **两种形状的开口**：**量值型**（数值偏了）与**结构型**（离散结论翻了：哪个最大、哪个
   周期、是否相等）。结构型更危险，因为它的输出仍然是"合法的"结构，看不出误差。
5. **尺度阈值**：绝对公差/网格在某个量级上整体失效（§2.7），不是渐变而是**相变**。
6. **可见的开口 vs 不可见的开口**。可见性（拒绝、`Unknown`、字段为 False）是**检查器的
   性质**，不是计算的性质。本仓库的"穷尽即 Unknown"正是一台把不可见变可见的机器。
7. **自指型开口**：由被约束者自己度量约束（§2.3）。这类开口的翻车率随"贴边程度"上升，
   而贴边程度＝实际/声明，可测。

## 4. 我们已有的防线（实例，不是设想）

- **完全精确的检查器**：判定为 `exact-only` 的实验是 `7` 个（`binary64` 与 `host` 都不落在验收路径上）。
- **显式排除主机字段**：`tests/python/test_reflexive_lattice_gate.py` 里
  `HOST_FIELDS = {"elapsed_before_final_write_ns", "peak_rss_kib", "limits_installed", ...}`
  ——对证据定义一个**声明的等价关系**，而不是假装逐字节相等。
- **拒绝 epsilon 判整数**：`experiments/lattice_polar/contract.json:55`、
  `experiments/reflexive_lattice_gate/contract.json:53`——"epsilon-based integrality … refused"。
  这正是对 §2.7 那类开口的正面拒绝。
- **穷尽枚举 + 保留见证 + 穷尽即 `Unknown`**：1451 条验收条目里，含 `Unknown`/残余措辞的
  16 条，含拒绝控制的 21 条。
- **"验收测试无浮点值"的声明**：10 条，**9 条成立**。

## 5. 一处真实的不符（声明的裂缝）

7 条声明里有一条不成立：`adva.bounded-experiment.hns-wall-localization.v0`
——它的检查器在同一行既做验收又读时钟：

```
experiments/hns_wall_localization/calibration.py:527  [host]  "within_time_budget": (time.monotonic() - started) <= cont…
```

严格读，声明说的是"验收测试中**没有浮点值**"，而这里是一个由时钟导出的**布尔**，不是浮点值；
它没有违反字面声明。**这恰恰是要点**：开口不在浮点里，而在**未被声明的依赖**里——声明的
措辞管住了"值"，没管住"什么可以决定或记录一个验收字段"。这条不改，只记。

## 6. 分布（77 个实验）

| 判定 | 数目 | 含义 |
|---|---:|---|
| `imprecision-can-decide` | 38 | 有"决定判定的那一行"落在 `binary64` 或 `host` 上 |
| `imprecision-in-illustration-only` | 28 | 有浮点/主机量，但不决定判定 |
| `exact-only` | 8 | 只有精确构造 |
| `no-numeric-constructs` | 2 | 没有数值构造 |

含 `binary64` 的 22 个；含 `host` 的 59 个；含 `drift` 的 28 个；三者皆无的 7 个。

**并且这是对我自己假设的反证**：我原以为预算声明会贴边，实测相反——能比对的 14 组里，
最紧的一组只用掉声明预算的 **17.3%**，**没有一组超过 50%**。机制普遍，但在这台机器上离
翻车很远；风险不是"正在发生"，而是**没有任何实验声明自己可以贴边到什么程度**。

## 7. 复现与残余

```sh
python3 scripts/float_aperture_scan.py --json docs/maintenance/float-apertures.json
```

残余（本清单**不**成立的）：

- 扫描是**文本级**的：它看构造与所在行，不做数据流分析。一个浮点值经变量、JSON、子进程
  传递到验收处，可能被判为 `illustration-only`；反之亦然。
- `deciding` 的判据是"同一行上既有构造又有比较/断言"。跨行、跨函数的路径不在其中。
- 预算占比只能对**声明字段被识别到**的实验计算（69 个里只有 14 组可比）；其余预算写在
  `rules`、硬编码常量或别处。
- `binary64` 的存在**不等于**判定不可靠——本仓库 1451 条验收条目里，绝大多数是穷尽枚举、
  见证保留与拒绝控制，判定并不依赖某个近似比较。
- 这份清单不估计任何真实翻车概率。它列的是入口与形状。
