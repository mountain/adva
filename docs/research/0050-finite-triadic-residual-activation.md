# Finite Triadic Residual Activation

Status: exploratory finite calibration following
[`0049-triadic-universal-computation-form-plan.md`](0049-triadic-universal-computation-form-plan.md).

The executable fixture is
[`tests/python/test_triadic_residual_activation.py`](../../tests/python/test_triadic_residual_activation.py).

This note asks the first dynamic question generated by the three-computer
programme:

> When an observer has forgotten a distinction, can a later typed program make
> that residual observable again?

The finite result separates two residual channels that must not be conflated.

1. A residual retained as typed constructive **state** can be read by a later
   spatial program.  Together with a temporal gate and an explicit schedule,
   it becomes a future spatial distinction.
2. A residual retained only in an audit **history** is not readable by the
   current extensional program core.  Programs that do not inspect history
   preserve extensional equality under every schedule in the declared machine.

The first channel is activatable.  The second is inert for the selected
language, although a finer history observer distinguishes it immediately.
This is not a defect: it is the exact boundary between observer refinement and
future program activation.

The fixture also computes the balanced binary parity pair.  Two `2 x 2 x 2`
relations have identical three pairwise marginals but opposite global parity.
This supplies a minimal static triadic phase that the dynamic activation
experiment can use as a baseline.

The host-side scheduler and finite state machine are research objects only.
Rust-authoritative Adva code checks the arithmetic spatial update

\[
x^+=x+t k.
\]

Python does not authorize a stable interpreter, scheduler, state transition,
or contextual equivalence.  The note adds no stable residual, activation,
context, modality, three-computer, energy, or logic API; does not modify
`claims.toml`; and does not change the active `ProgramSlice` priority.

## 0. Executive result

Let a finite fine state be

\[
s=(t,x,k,h),
\]

where

- \(t\in\{0,1\}\) is a temporal gate;
- \(x\in\mathbf Z\) is a spatial value;
- \(k\in\{-1,+1\}\) is a constructive state;
- \(h\) is an audit history.

The coarse observer reads only

\[
Q_X(s)=x.
\]

Start from

\[
s_+=(0,0,+1,h_+),
\qquad
s_-=(0,0,-1,h_-).
\]

The coarse observer identifies them:

\[
Q_X(s_+)=Q_X(s_-)=0.
\]

Use two programs:

\[
p_t:t\longmapsto1,
\]

and

\[
p_X:(t,x,k)\longmapsto x+t k.
\]

Under the schedule

\[
\sigma=(t,X),
\]

the two runs become

\[
s_+\longmapsto(1,0,+1)\longmapsto(1,+1,+1),
\]

and

\[
s_-\longmapsto(1,0,-1)\longmapsto(1,-1,-1).
\]

Hence

\[
Q_X(\operatorname{Run}_\sigma(s_+))
\ne
Q_X(\operatorname{Run}_\sigma(s_-)).
\]

The constructive residual has been activated into a spatial characteristic by
a temporally ordered continuation.

The reverse two-step schedule

\[
\sigma'=(X,t)
\]

does not yet separate the states.  The spatial program reads the closed gate
before the temporal program opens it.  A third spatial step activates the
residual:

\[
(X,t,X).
\]

Thus activation is not determined by the program multiset alone.  Schedule is
semantic data.

# Part I. A static irreducible triadic phase

## 1. Two balanced binary relations

Let

\[
T=X=K=\{0,1\}.
\]

Define

\[
\Lambda_0
=
\{(t,x,k)\mid t\oplus x\oplus k=0\},
\]

and

\[
\Lambda_1
=
\{(t,x,k)\mid t\oplus x\oplus k=1\}.
\]

Each relation contains four triples.  In each of the three pairwise
marginalizations, every binary pair occurs exactly once:

\[
\sum_k1_{\Lambda_0}(t,x,k)
=
\sum_k1_{\Lambda_1}(t,x,k)
=1,
\]

and cyclically for \((x,k)\) and \((k,t)\).

Therefore all pairwise marginal tables agree, while

\[
\Lambda_0\ne\Lambda_1.
\]

## 2. Exact enumeration

The fixture enumerates all four-point subsets of the binary cube and retains
those with the same three pairwise marginals as \(\Lambda_0\).  Exactly two
survive:

\[
\{\Lambda_0,\Lambda_1\}.
\]

The remaining global choice is the parity phase

\[
\Theta\in\mathbf Z/2\mathbf Z.
\]

This is a finite calibration of three-way interaction, not a claim that parity
is a new invariant in mathematics.  Binary contingency tables, log-linear
models, database dependencies, and contextuality supply established baselines.

## 3. Sections recover what marginals forget

Pairwise marginalization forgets which third value completes a pair.  An
opposite-pair section retains it:

\[
S_K^{\Theta}(t,x)
=
\{k\mid(t,x,k)\in\Lambda_\Theta\}.
\]

For every \((t,x)\),

\[
S_K^0(t,x)
\ne
S_K^1(t,x).
\]

Thus the full section family determines the ternary relation even when the
three unconditioned pairwise marginals do not.

The logical lesson is narrow but important: a 3-form logic must not replace
opposite-pair sections by pairwise projections.

# Part II. The activation machine

## 4. Fine and coarse states

The fine state carrier is

\[
S
=
\{0,1\}
\times
\mathbf Z
\times
\{-1,+1\}
\times
H.
\]

The coarse spatial observer is

\[
Q_X:S\to\mathbf Z,
\qquad
Q_X(t,x,k,h)=x.
\]

Its initial fibre over zero contains both selected states:

\[
Q_X^{-1}(0)
\supseteq
\{s_+,s_-\}.
\]

The residual is not discarded.  The fine preimage records both construction
signs and both histories.

## 5. Three bounded programs

The temporal program opens the gate:

\[
p_t(t,x,k,h)
=
(1,x,k,h\cdot[\mathrm{open}]).
\]

The spatial program executes the Rust-checked Adva arithmetic:

\[
p_X(t,x,k,h)
=
(t,x+t k,k,h\cdot[\mathrm{activate}]).
\]

The constructive baseline program preserves the sign and appends an audit
token:

\[
p_K(t,x,k,h)
=
(t,x,k,h\cdot[\mathrm{hold}]).
\]

The constructive program is intentionally inert.  The experiment isolates
activation of an already retained construction state; it does not yet test
code generation or installation.

## 6. Rust-checked arithmetic boundary

The spatial update is represented by the Adva program

```text
activate-construction(space, gate, construction)
  = space + gate * construction
```

The Rust core validates its typed graph, occurrences, uses, evaluation, and
history.  SymPy is only an independent symbolic oracle for the polynomial
identity.

The outer state carrier and scheduler remain Python research fixtures.  This
division must be explicit: the test does not establish a stable triadic
transition semantics.

# Part III. Contextual activation

## 7. A schedule as a finite context

For the current fixture, a context is a finite word

\[
\sigma\in\{t,X,K\}^*.
\]

Execution applies the selected programs from left to right.  The exact word is
retained in the run report.

A schedule activates two states for observer \(Q_X\) when

\[
Q_X(\operatorname{Run}_\sigma(s_+))
\ne
Q_X(\operatorname{Run}_\sigma(s_-)).
\]

## 8. Minimal activation context

The fixture exhaustively enumerates schedule words by length.  No word of
length zero or one separates the states.  At length two, exactly the required
order appears:

\[
\sigma_{\min}=(t,X).
\]

Its resource-count vector is

\[
\mathbf C(\sigma_{\min})=(1,1,0),
\]

counting temporal, spatial, and constructive steps.

This is not yet the directional energy vector.  Resource counts and
characteristic energy remain distinct until an explicit calibration relates
them.

## 9. A context-defined proposition

The activating context generates the proposition

\[
P_{(t,X)}
=
\{s\mid
Q_X(\operatorname{Run}_{(t,X)}(s))>0
\}.

Then

\[
s_+\in P_{(t,X)},
\qquad
s_-\notin P_{(t,X)}.
\]

Before execution, the coarse proposition \(x>0\) contains neither state.  The
continuation creates a future spatial test from temporal order and constructive
state.

This supplies one finite example of an admissible proposition generated by an
executable context rather than selected from an arbitrary powerset.

## 10. Modal reading

The context admits a provisional dynamic reading:

\[
\langle t;X\rangle(x>0).
\]

It means that executing the declared temporal step followed by the declared
spatial step reaches the positive spatial region.

The fixture does not introduce modal syntax or rules.  It only computes the
finite satisfaction set that such a modality would denote.

# Part IV. History residuals remain different

## 11. Same state, different audit history

Now take

\[
r=(t,x,k,h),
\qquad
r'=(t,x,k,h'),
\qquad
h\ne h'.
\]

All three programs read only \((t,x,k)\).  They append the same token selected
by the same schedule but never branch on history.

Therefore equality of the extensional projection

\[
\pi(t,x,k,h)=(t,x,k)
\]

is preserved by every program step:

\[
\pi(r)=\pi(r')
\Longrightarrow
\pi(p_D(r))=\pi(p_D(r'))
\]

for

\[
D\in\{t,X,K\}.
\]

By induction over schedule words,

\[
\pi(\operatorname{Run}_\sigma(r))
=
\pi(\operatorname{Run}_\sigma(r'))
\]

for every finite \(\sigma\).

## 12. Inert does not mean deleted

A history observer still distinguishes the runs:

\[
Q_h(r)=h
\ne
h'=Q_h(r').
\]

The distinction is therefore:

- **observer refinement:** inspect history directly;
- **program activation:** let a later admitted program convert hidden state
  into a different ordinary output.

The current core supports the first through checked histories.  It does not
expose history as ordinary program data, so it cannot perform the second for a
history-only residual.

Adding a host callback that branches on `function.history` would fabricate an
activation result outside Adva semantics.  The fixture deliberately forbids
that shortcut.

## 13. The finite classification

The experiment therefore produces:

| residual | later program can read it? | coarse spatial future | status |
|---|---:|---:|---|
| construction sign \(k\) | yes | separates under `(t,X)` | active |
| audit history \(h\) | no | remains equal for every admitted schedule | inert in this machine |
| unsearched larger program class | unknown | not decided | `Unknown` |

The last row matters.  Inertness is always relative to a declared program and
context class.

# Part V. Implications for 3-form logic

## 14. Static support inclusion is insufficient

At the initial coarse observer,

\[
Q_X(s_+)=Q_X(s_-).
\]

A logic containing only current spatial supports cannot distinguish the two
states.  The future context `(t,X)` generates a separating proposition.

Thus the proposition family should depend not only on current supports but on
admitted executable contexts:

\[
\mathcal L_Q^{\mathrm{ctx}}
=
\{P_C\mid C\in\mathcal C_Q\}.
\]

## 15. Entailment needs program transport

If a context \(F\) uniformly transports every realization of \(A\) into a
realization of \(B\), then it is a candidate proof-relevant entailment:

\[
A\vdash_Q^F B.
\]

The current fixture supplies only one context-generated predicate, not a full
transport calculus.  It nevertheless identifies the missing witness that
support inclusion alone does not provide.

## 16. Structural rules become empirical questions

The schedule comparison shows that exchange is not automatic:

\[
t;X
\ne
X;t
\]

for the activation observation.

Likewise, contraction and weakening must be tied to explicit copy and discard
programs.  Cut should correspond to checked context composition.  A future
natural deduction must derive its structural rules from admitted program
operations rather than import them silently.

## 17. Genuine triadic dependence

The activation requires:

- constructive sign \(k\);
- temporal gate \(t\) and its ordering; and
- spatial observation \(x\).

Removing any one role destroys the selected two-step distinction.  This is a
stronger triadic calibration than placing three labels on one scalar
calculation, although it is still a deliberately small state machine.

# Part VI. Algorithm and verification boundary

## 18. Finite activation search

For a maximum word length \(B\):

1. enumerate schedules in nondecreasing length;
2. execute each schedule on both fine states;
3. compare the declared observer outputs;
4. return the first separating length and every minimal witness; or
5. return `Unknown` beyond the declared bound unless the context space is
   independently proved closed.

The current fixture finds a witness, so no nonexistence inference is needed.

## 19. Authority boundary

Rust certifies:

- the arithmetic program graph;
- its operation types and occurrences;
- its finite evaluations; and
- its checked history.

Python supplies:

- the finite state tuple;
- the three host-side transition wrappers;
- schedule enumeration;
- pairwise marginal enumeration;
- contextual observation; and
- the research classification report.

SymPy supplies only an independent exact polynomial oracle.  Neither Python
nor SymPy authorizes a new Adva machine law.

## 20. Complexity

For three program labels and schedule bound \(B\), naive enumeration checks

\[
\sum_{d=0}^B3^d

\]

words.  This is acceptable for the first finite fixture and deliberately
exposes the later need for state quotienting, automata minimization, or
symbolic search.

# Part VII. Results and next gates

## 21. What the fixture establishes

Within the declared finite machine, the fixture establishes:

1. two balanced binary 3-forms with identical pairwise marginals and opposite
   global parity;
2. exact enumeration of the two compatible balanced fillings;
3. opposite-pair sections that distinguish the fillings;
4. one Rust-checked spatial activation program;
5. one coarse observer fibre containing two constructive signs;
6. exact activation under the schedule `(t,X)`;
7. exact nonactivation under the reversed two-step schedule `(X,t)`;
8. minimal schedule length two by exhaustive finite search;
9. one context-defined spatial proposition;
10. an extensional congruence for history-blind transitions; and
11. separation of state activation from direct history observation.

## 22. What it does not establish

The fixture does not establish:

- a stable triadic machine or scheduler;
- U0 uniform programmability;
- code-as-data or a universal interpreter;
- activation of actual Adva history by an Adva program;
- a general contextual-equivalence decision procedure;
- a complete context-generated logic;
- implication, modalities, or natural-deduction rules;
- a general irreducible triadic invariant;
- a physical energy interpretation;
- a solution to the global L/R problem; or
- a new result about binary parity outside the Adva research programme.

## 23. Next decisive experiments

The next steps should be:

1. replace the host scheduler with the first U0 research run report after the
   code-as-data and process-slice dependencies are met;
2. generate a finite typed context grammar rather than schedule words alone;
3. compute the complete context-definable proposition family and compare it
   with the ambient powerset;
4. search for semantic support inclusion without a constructive transporter;
5. test identity and cut through explicit context composition;
6. test exchange, contraction, and weakening through actual ordered programs;
7. transport the parity phase through one crossing and observer quotient; and
8. seek an activation that changes future extensional energy, not only value.

## 24. Conservative conclusion

The first dynamic 3-form result is mixed and useful:

> A residual retained as typed state can be activated by a later program and
> schedule; a residual retained only as unreadable audit history remains
> extensionaly inert in the current program fragment.

This distinction supplies a concrete basis for context-generated propositions,
proof-relevant entailment, schedule-sensitive structural rules, and the future
state quotient of a triadic universal machine.
