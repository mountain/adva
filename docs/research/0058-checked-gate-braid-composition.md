# Checked Gate--Braid Composition on the Three-Bracket Boundary

Status: bounded joint calibration following
[`0056-rust-checked-triadic-generator-presentations.md`](0056-rust-checked-triadic-generator-presentations.md)
and
[`0057-typed-vacua-constant-boundary-braids.md`](0057-typed-vacua-constant-boundary-braids.md).

The executable fixture is
[`tests/python/test_checked_gate_braid_composition.py`](../../tests/python/test_checked_gate_braid_composition.py).

Note 0057 separated reversible braid transport from the noninvertible updates
needed for computation.  This note performs the next advertised experiment:
compose its exact colored braid history with one full-boundary, Rust-checked
active gate.

The selected gate is `checked-braid-gate/spatial-update`, a test-local
redeclaration of the exact `spatial-update` presentation from note 0056, with
finite action

\[
X(t,x,k)=(t,t\wedge k,k).
\]

The bounded result is negative but decisive:

> The checked gate composes with typed braid transport, and its value action is
> natural under every elementary colored crossing.  Under the current bridge,
> however, crossings move complete colored ports while the gate reads only
> their colors and values.  Every pure braid is therefore in a contextual
> kernel of the finite computation.  Full twists and zero-winding pure
> commutators remain exact audit history, but the selected checked gate cannot
> read them through the declared bridge.  The braid layer is a transport
> sidecar, not yet a computationally
> coupled substrate.

This does not refute a future history-sensitive machine.  It identifies the
missing primitive that such a machine must supply.

---

## 0. Executive result

The fixture keeps four claims at different authority levels:

| layer | checked object | bounded result |
|---|---|---|
| active value | Rust execution of `spatial-update` | nonidentity idempotent, rank 4 on 8 states |
| active resource | Rust IR, cut, and slice | `copy` twice, `discard` once, `mul` once |
| reversible transport | research-side colored ports and faithful Artin action | exact braid history with bijective endpoint routing |
| mixed bridge | finite exhaustive comparison | crossing/gate squares commute on colored values |

The last two rows are an executable research model.  They are not a new Rust
braid API or a Rust certificate for signed crossings.

For public closed schedules generated by these crossings and this one gate,
the color-indexed finite state quotient is only

\[
\{1,X\}.
\]

Every schedule without the gate acts as the identity on color-indexed values.
Every schedule containing the gate acts as $X$, because $X^2=X$.  The fixture
computes the complete 12-element finite closure: six boundary permutations,
each paired with both transformations.

# Part I. One boundary, two explicit coordinate orders

## 1. Public and checked orders

The public boundary remains

\[
\Omega_{\partial}=K\otimes X\otimes t=\texttt{\{\}[]()}.
\]

The checked Adva function uses parameter order

\[
(t,x,k).
\]

The bridge is by name, not by tuple position:

| glyph | color | checked parameter |
|---|---|---|
| `{}` | $K$ | `construction` |
| `[]` | $X$ | `spatial` |
| `()` | $t$ | `temporal` |

This reversal matters.  A transported gate must continue to update the
$X$-colored port even when that port is no longer in the middle position.

## 2. The selected active gate

The checked presentation is a three-input, three-output endomorphism:

\[
X:t\otimes X\otimes K\longrightarrow t\otimes X\otimes K.
\]

It is not treated as an already established binary gate.  Writing
$g_{DX}:D\otimes X\to D\otimes X$ would first require a definition and a
checked presentation of the composite driver $D$.

On all eight Boolean inputs, Rust execution verifies

\[
X^2=X,
\qquad
X\ne1,
\qquad
\operatorname{rank}(X)=4.
\]

Each of its four outputs has exactly two preimages.  The forgotten bit is the
old spatial value $x$.

Its checked operation multiset is

\[
\{\texttt{copy}:2,\texttt{discard}:1,\texttt{mul}:1\}.
\]

The output source pattern is

\[
(\{s_t\},\{s_t,s_K\},\{s_K\}).
\]

The old $s_X$ is absent from the final frontier, while the discard remains
in the checked internal history.

# Part II. Typed transport and the mixed square

## 3. Transport moves complete colored ports

A finite transport frame is a sequence

\[
((c_1,v_1),(c_2,v_2),(c_3,v_3)),
\]

with exactly one color each of $K,X,t$.  A crossing
$\sigma_i^{\pm1}$ swaps two complete pairs.  It never separates a value
from its color, duplicates a pair, or discards a pair.

The sign is retained by the faithful Artin action on $F_3$.  It does not
change endpoint routing:

\[
\pi(\sigma_i)=\pi(\sigma_i^{-1})\in S_3.
\]

This is intentional.  It exposes exactly which observations can and cannot
distinguish over-crossings from under-crossings.

## 4. The color-relative gate family

For every permutation $w$ of the three colors, define $X_w:w\to w$ by:

1. locate $t,X,K$ by color;
2. call the checked function with named inputs `temporal`, `spatial`, and
   `construction`;
3. put each named output back on its original color.

No silent coercion or positional alias is used.

With schedules written left to right, every elementary typed crossing

\[
b:w\longrightarrow w'

\]

satisfies the finite mixed square

\[
X_w;b
=
b;X_{w'}.
\]

The fixture exhausts all six boundary permutations, all eight Boolean states,
and all four signed elementary crossings.  It also verifies that transport
preserves the multiset of whole ports.  Each side invokes the same checked
two-copy, one-discard, one-multiply active gate; Python transport adds no
modeled resource event.

This is extensional naturality plus a coarse resource comparison.  It is not
a Rust-checked naturality 2-cell for source and occurrence identifiers,
because Adva does not yet expose a signed braid morphism on those objects.

## 5. Why color-relative typing is essential

As a negative control, let a fake gate always overwrite the middle slot with
the conjunction of the left and right slot values.  It agrees with $X$ on
the public order $KXt$, but after $\sigma_1$ it overwrites $K$, not $X$.

For the input

\[
(t,x,k)=(1,0,1),
\]

the two sides of the mixed square become

\[
((X,1),(K,1),(t,1))
\ne
((X,0),(K,0),(t,1)).

\]

Thus a tuple-position implementation is observably wrong even though it
passes the gate formula on the one public ordering.

# Part III. Coherence versus residual history

## 6. Artin-equal paths

The fixture reuses the faithful Artin representation from note 0057.  It
checks

\[
\sigma_1\sigma_2\sigma_1
=
\sigma_2\sigma_1\sigma_2

\]

as exact automorphisms of $F_3$, not merely as endpoint permutations.
Conjugating the checked gate by either spelling gives the same finite run and
the same blockwise Artin-normalized presented history.  This case is
`Coherent` by a
braid witness.

## 7. Same state, retained pure-braid residual

Two pure braids are used as stronger probes:

\[
\Delta^2=(\sigma_1\sigma_2)^3,

\]

and

\[
c=A_{12}A_{23}A_{12}^{-1}A_{23}^{-1}.

\]

Both return the public colors to $KXt$, and both have nonidentity Artin
actions.  The commutator additionally has zero signed winding for every
colored pair:

\[
\lambda(c)=(0,0,0).

\]

The fixture inserts either pure braid into several prefixes and suffixes
containing further crossings and checked gate calls.  Every one of the eight
input states has the same final frame with or without the insertion.

Nevertheless,

\[
\operatorname{history}(p;X)
\ne
\operatorname{history}(X;p)

\]

for these nontrivial $p$.  Maximal adjacent braid blocks are compared by exact
Artin action,
while gate separators and their order are retained.  Under the presently
authorized witnesses this outcome is `Residual`, not `Coherent` and not
`ActiveDefect`.

## 8. Conditional contextual-kernel theorem

Let a mixed trace alternate braid blocks and color-relative $X_w$ gates.
Assume:

1. a braid block acts on finite ports only through its endpoint permutation;
2. the gate reads only current named color values;
3. later gates and observers obey the same restriction.

Then replacing any braid block by another block with the same endpoint
permutation preserves the result of every continuation.  Since
$P_3=\ker\pi$, every $p\in P_3$ satisfies

\[
C[p]\sim_{\mathrm{value}}C[1]
\]

for every context $C[-]$ admitted by these assumptions.

Proof: equal endpoint permutations produce the same ordered colored frame.
The next gate therefore receives the same three named inputs and produces the
same named outputs.  Induction over the remaining trace proves contextual
equality.

This is a theorem about the declared observation model.  It is not a
syntactic braid equality, a direct-product theorem, or permission to erase
Artin, gate, source, occurrence, copy, or discard history.

# Part IV. A tempting lift that is not yet authorized

## 9. Why source sets are not free-group words

One can manufacture an apparently stronger coupling by encoding the checked
source pattern as the free-group endomorphism

\[
(t,X,K)\longmapsto(t,tK,K)

\]

and composing it with the Artin action.  In that invented model a full twist
need not commute with the gate.

The current checked evidence does not authorize this encoding:

- output sources are sets, not ordered noncommutative words;
- copy lineage supplies parent/child occurrence relations, not group
  multiplication;
- no rule assigns inverses or conjugation to source identifiers;
- the Rust `swap` operation is symmetric and does not distinguish
  $\sigma_i$ from $\sigma_i^{-1}$.

Therefore such a free-group lineage lift is a useful future hypothesis, but
not a result of this note.  A real coupling requires a checked ordering or
history action rather than an arbitrary Python encoding.

# Part V. Reversible dilation as a resource control

## 10. One-step dilation with explicit garbage

The finite gate can be embedded for one use into the four-bit bijection

\[
D(t,x,k,g)=\bigl(t,g\oplus(t\wedge k),k,x\bigr).

\]

Its inverse is

\[
D^{-1}(t,y,k,x_{\mathrm{old}})
=
\bigl(t,x_{\mathrm{old}},k,y\oplus(t\wedge k)\bigr).

\]

With a prepared $g=0$, the first three outputs equal $X(t,x,k)$, and the
fourth output retains the old spatial bit.  Exhaustive enumeration verifies
that $D$ is a permutation of all sixteen extended states.

One garbage bit is information-theoretically minimal in this finite model:
every output of $X$ has two preimages.

## 11. Why the dilation is not the same gate

The dilation changes the boundary and does not preserve iteration.  Applying
the same four-wire permutation twice does not simulate $X^2=X$ from the
same prepared interface; the once-clean garbage wire now contains the old
$x$.

Two general no-go arguments explain the fixture:

1. A homomorphic image of an idempotent into a group must be the identity, so
   a nontrivial $X$ has no faithful same-law lift into reversible units.
2. If $p:E\to S$ is surjective, $U:E\to E$ is bijective, and
   $pU=Xp$ globally, then $pU$ is surjective while $Xp$ has only four
   outputs.  This is impossible.

Fixed-boundary, all-state, globally compositional repeated reversible
simulation therefore requires fresh or growing history, a changing boundary,
or an explicit reset/discard step.  The dilation is a resource-accounting
control, not a current Adva or XOR primitive.

# Part VI. Consequence for the universal-machine question

## 12. What has now been established

The three-bracket proposal now has a precise small calculus:

- one fixed public typed boundary $KXt$;
- exact, nontrivial reversible braid histories;
- one Rust-checked noninvertible active endomorphism;
- a verified typed composition rule;
- explicit preservation of gate resource loss;
- a proof that the current finite observer cannot read pure-braid history.

This is more than three inert punctuation marks, but it is still far short of
general computation.  In the current color-natural finite quotient, arbitrary
braiding adds no new state transformations beyond $1$ and $X$.

## 13. The next decisive primitive

The next experiment should not add more braid words.  It should add one
Rust-checked observer or gate $O$ that consumes an authorized history datum
and produces a visible difference:

\[
O(\beta)\ne O(\beta p)

\]

for some $p\in P_3$, either in output value, enabled rewrite, or checked
lineage.  A difference confined to a Python log is insufficient.

Possible implementations require at least one new checked ingredient:

- a signed crossing or ordered-lineage representation;
- a history token admitted as an explicit input resource;
- a gate whose enabledness depends on a certified residual;
- or a growing garbage/history boundary with checked readback.

Until such an observer is built, the bounded sidecar conclusion remains in
force for this machine family.  Success would be the first evidence that
transport history participates in computation.
