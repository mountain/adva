# Research 0256: Independent construction from an abstract continuation description

Status: **bounded finite constructor comparison after one pre-execution
supervisor correction**. This note adds no native operation, framework
`accept`, executable continuation permission, new fuel or vocabulary word.

## Question and frozen boundary

[Research 0255](0255-held-out-continuation-receiving.md) showed that Python and
Node receivers agree on two new continuation families emitted by a third Perl
process without answer labels. That still leaves a constructor common-mode
possibility: the generated bytes may reflect one implementation's accidental
encoding rather than the declared abstract instances.

This run asks a narrower question. If a fourth implementation reads only an
abstract description of the same `rho` and `tau` instances, runs before the
Perl output path exists, and independently derives every digest-linked object,
does it emit the same fourteen canonical per-case JSON payloads as the frozen
Perl constructor?

The project-original
[`abstract-instances.tsv`](../../experiments/continuation_constructor_crosscheck/abstract-instances.tsv)
contains only case, attempt, terminal state, problem and exact natural-number
budget fields. It contains no expected receiver outcome, JSON object, digest or
constructed byte. The new
[`Constructor.java`](../../experiments/continuation_constructor_crosscheck/Constructor.java)
uses Java 17 standard-library file and SHA-256 facilities plus a separately
implemented canonical JSON encoder; it imports no JSON package, Perl source or
receiver. The supervisor launches Java first and verifies that the Perl output
directory is absent both before and after Java exits. Only then does it launch
the unchanged Research 0255 Perl constructor.

The [initial contract](../../experiments/continuation_constructor_crosscheck/contract.json)
froze two constructor processes, zero receivers and targets, ten seconds and
40,000 work units per constructor, thirty outer seconds, 500 comparison units,
four comparison-only controls, zero search and no correction replay. The
[correction contract](../../experiments/continuation_constructor_crosscheck/correction-contract.json)
changes only the failed supervisor condition described below and consumes the
sole implementation correction.

## Retained pre-execution failure and correction

The first supervisor invocation stopped before launching either constructor.
It correctly checked that the Java source contains no `constructor.pl` path,
then incorrectly rejected any occurrence of the word `Perl`. The Java source
necessarily uses that word in its explanatory comment and in the negative
result field `perl_output_read`.

This is retained as
[`PreExecutionImplementationFailure`](../../experiments/continuation_constructor_crosscheck/evidence/prior-preexecution-failure.json):
zero child and target processes, zero output files and no research result. The
sole correction removes the overbroad word check. It preserves the exact
`constructor.pl` path exclusion and, more importantly, the executable ordering
check that Java finishes while no Perl output path exists.

## Result

The correction replay passed 37 explicit supervisor checks. For both `rho` and
`tau`, Java and Perl independently derived byte-identical versions of:

1. source pending anchor;
2. recovery anchor;
3. terminal anchor;
4. resolution query;
5. resolution receipt;
6. problem--history--budget continuation;
7. continuation gate query.

All fourteen payloads were canonical JSON and their bytes, not merely their
parsed values, matched. The implementation-specific manifests are retained but
are intentionally not compared: they report different constructor identities
and provenance.

The primary comparison returned `ImplementationAgreement`. Four negative
controls each returned `UnknownImplementationAgreement`:

- changing one canonical terminal byte family;
- omitting one payload from the declared coverage;
- adding a newline to make one representation noncanonical;
- claiming both results have the same source coordinate.

No receiver or target process ran. No continuation, effect, retry, refund,
mutation, native or `free` authority was created.

## Meaning and residual

No new word is justified. `ImplementationAgreement` and
`UnknownImplementationAgreement` remain local result labels. The result removes
one narrow explanation for Research 0255: the fourteen bytes do not depend
solely on the Perl implementation or JSON::PP's canonical encoder. It helps
Mingli and later agents distinguish an abstract continuation description from
one constructor's serialization while retaining the exact problem, ordered
history, budget and digest chain. Practical value for Jiamin's task remains
unmeasured.

This is not independent human review or receipt truth. Both routes share the
same repository, host, SHA-256 semantics, Python comparison supervisor and an
abstract description chosen after the frozen Perl code already existed. The
Java implementation was written with knowledge of the declared Perl semantics;
agreement cannot exclude a shared specification or authoring defect. Java,
Perl and Python are external dependencies, not native Adva implementations.

This bounded result is not added to `docs/claims.toml` in this round. The prior
public transfer boundary for that large UTF-8 registry remains unresolved; this
note therefore records a finite unpromoted result without risking another
truncated registry update.

The experiment does not establish Research 0090 coverage, Research 0092
promotion, native `communicate`, `accept`, `free` or `Close`, M6 closure,
hypothesized arithmetic truth or arithmetic universality.

The next minimum step is to freeze two generic spec-consuming constructor
sources before introducing a third abstract instance that neither source
contains. The new instance should then be supplied only as data; exact output
agreement or explicit `UnknownImplementationAgreement` would distinguish
constructor generalization from agreement on two already known descriptions.
