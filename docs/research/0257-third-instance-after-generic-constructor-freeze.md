# Research 0257: A third instance after generic constructor freeze

Status: **bounded finite constructor-generalization comparison**. This note adds
no native operation, framework `accept`, executable continuation permission,
new fuel or vocabulary word.

## Question and frozen boundary

[Research 0256](0256-independent-construction-from-an-abstract-continuation-description.md)
showed that Java and Perl could derive the same fourteen canonical payloads
from two abstract rows. Both implementations were nevertheless written with
knowledge of those rows. The remaining narrow question was whether the
construction sources could be fixed first and then applied to an instance that
neither source contains.

At the start of this round, main was
`3a6ba5571491342d0e211a56590a29b2407e284c`. It already contained PR 208 and
the KPB G4 successor `cf5f2ede2cc0e8c500eb975b1d8e24d7d8f46ba6`; no pull
request was open. This experiment changes no machine lock, consumer, frozen
predecessor evidence or claims-registry entry.

The [contract](../../experiments/continuation_constructor_generalization/contract.json)
freezes one route:

- exactly one later abstract instance;
- two generic constructor processes, one Java and one Perl;
- seven exact payload comparisons and four comparison-only controls;
- ten seconds and 40,000 counted units per constructor;
- 300 comparison units and thirty outer seconds;
- zero search candidates, receiver processes and target processes;
- zero implementation-correction replays.

The arithmetic domain is the exact natural-number budget
(41=23+18). Problem, ordered history and budget remain different typed
components. A comparison difference is
`UnknownImplementationAgreement`, not a semantic counterexample.

## Result and refusal controls

The sole research execution passed 37 explicit supervisor checks. Both
constructors independently emitted byte-identical canonical versions of:

1. source pending anchor;
2. recovery anchor;
3. terminal anchor;
4. resolution query;
5. resolution receipt;
6. problem--history--budget continuation;
7. continuation gate query.

The primary comparison returned `ImplementationAgreement` over all seven
payloads. Four controls returned `UnknownImplementationAgreement`:

- change one canonical terminal payload;
- remove one declared payload;
- append a newline to make one payload noncanonical;
- claim the two results have the same source coordinate.

No receiver or target ran. No continuation, effect, retry, refund, mutation,
native or `free` authority was created.

## Meaning and residual

No new word is justified. `ImplementationAgreement` and
`UnknownImplementationAgreement` remain local result labels. This result
removes one narrower explanation than Research 0256: agreement is not confined
to two instance descriptions already present when both compared sources were
written. The sources accepted a third instance supplied only as later data and
derived the same finite byte family.

This helps Mingli and later agents separate a generic construction rule from
examples known during authoring. It can also help a future collaborator audit
whether a claimed reusable protocol merely memorizes its fixtures. Practical
value for Jiamin's task remains unmeasured.

The result is not receipt truth, independent human review or mathematical
generalization beyond this one later row. Both sources were written by the same
agent, share the same written schema, host, SHA-256 meaning and Python
supervisor, so common-mode defects remain possible. Java, Perl and Python are
external dependencies, not native Adva implementations.

This bounded result is not added to `docs/claims.toml` in this round. The
large-registry transfer boundary noted in Research 0256 remains unresolved; the
finite result therefore stays unpromoted instead of risking another truncated
registry update.

The experiment does not establish Research 0090 coverage, Research 0092
promotion, native `communicate`, `accept`, `free` or `Close`, M6 closure,
hypothesized arithmetic truth or arithmetic universality.

The next minimum step is adversarial: freeze a third constructor written
against the abstract schema but without seeing either existing source, then
give all three the same later instance. Pairwise byte agreement would still be
finite; any divergence must remain explicit rather than being normalized by
the Python supervisor.
