Status: completed bounded construction and executed calibration, 2026-09-16. Base:
`6c01852`.

Direction: Mingli Yuan. Design, construction, execution and record:

## 1. What was missing after the static calibration

[The Futamura note](futamura-projections-in-adva-terms.md) executed the first
projection for a fully static source family: 129 frozen arithmetic trees, and every
residual came out as a constant, because the source program was the entire input.
That leaves the substance of "compiling" untested — a residual that must compute a
*function* of a dynamic input, that is, residual **code**.

This calibration keeps a live dynamic input. The source language is the declared
subset of the machine's own instruction language that the scaling preflight already
uses — `input d`, `return s`, two data slots, fixed length three — so a source
program is the static part and the object input value `x` is the dynamic part.

## 2. The three programs, all in one language

| Role | Program | Size |
| --- | --- | --- |
| Interpreter `I` | generated by `experiments/self_interpretation_scaling/check.py`, reused unchanged | 103 instructions |
| Compiler `C` | generated in `experiments/futamura_dynamic_residual/check.py` | 41 instructions, 12 registers, 11 instruction kinds |
| Residual `C(p)` | emitted as data, instantiated, and executed directly | 1 or 2 instructions |

All three are programs in the research data-machine language, and the compiler both
*reads* and *writes* the same declared program encoding: a program node (tag 2) whose
fields are instruction nodes, tag 0 `input dst` and tag 1 `return src`, over two data
registers. The emitted residual is therefore a program in the language the compiler
itself consumes, which is the leg self-hosting needs.

The compiler's whole rule is one sentence, because a rule that cannot be read cannot
be checked:

> Keep the last instruction that writes the returned slot, together with the return;
> drop every other instruction.

## 3. What was executed

All eight source programs `input a; input b; return s` over two slots, each with two
dynamic values, sixteen cases in total:

| Quantity | Value |
| --- | --- |
| Interpreted | status and value; 41 to 50 native steps, 728 in total |
| Compiled | 36 to 38 native steps, 592 in total |
| Residual | 1 or 2 instructions; 1 to 2 native steps, 28 in total |
| Agreement | interpreted and directly executed residual agree in status and value, 16 of 16 |
| Six programs that write the returned slot | residual is 2 instructions, returns the dynamic value |
| Two programs that read a slot nothing wrote | residual is 1 instruction, and execution is **refused** with `uninitialized register` — the same outcome as interpretation |

Two points carry the result beyond bookkeeping. First, the refractory cases are kept
as refusals: the compiler drops the dead inputs and the residual still refuses, so the
calibration cannot pass by turning a failure into a value. Second, the economics here
invert the static calibration's: there the compile cost dominated and two uses were
needed before compiling beat interpreting, while here one compile plus one residual
run (592 + 28 = 620) is already cheaper than interpreting sixteen times (728), and
per case about 38.75 steps against 45.5. The reason is measured rather than asserted —
`I` is a 103-instruction interpreter paying dispatch per object instruction, while `C`
is a 41-instruction data transformation that does not execute the source program at
all. Compilation's pay-off depends on the ratio between those two programs, and both
calibrations record their own ratio instead of generalising from one of them.

## 4. The loader boundary, unchanged and now load-bearing

The residual is emitted as data and becomes an executable program only through a host
step in the checker. That boundary was already recorded in the static calibration; with
a dynamic residual it becomes the thing that stands between "a compiler in the
language" and "a self-hosting toolchain", because nothing in the machine turns emitted
program data into a program. A compiled artifact can be *interpreted* in-language, but
it cannot be *run* in-language.

## 5. Where the projection ladder now stands

- **Projection 1, fully static family**: executed
  ([static calibration](futamura-projections-in-adva-terms.md)); residuals are constants.
- **Projection 1, live dynamic input**: executed here; residuals are code, with
  refusals preserved, for a two-opcode two-slot subset.
- **Projection 2** (`mix(mix, I)`, a compiler produced by self-application): blocked.
  The compiler it would have to produce is a program in the language it compiles; this
  compiler uses 11 instruction kinds and 12 registers over programs of 2 opcodes and
  3 instructions, and the measured floors stand at 295 instructions for a
  nineteen-opcode meta against a declared 128 and 169 data nodes against 127.
- **Projection 3** (`mix(mix, mix)`, a compiler generator): blocked by the same three
  facts, plus the missing loader.

## 6. What this does not establish

- No general optimiser, no stable specializer, no cost or correctness certificate
  beyond the sixteen executed cases, and no wall-clock performance claim: the steps
  counted are steps of the research data machine.
- The source language is a two-opcode, two-slot, fixed-length subset, and one
  transformation is performed. Residual quality in general, dynamic register
  allocation, loops, recursion and non-linear control are untouched.
- The compiler is not derived from the interpreter by a specializer; the checked
  statement is that the residuals it emits commute with interpretation under the
  declared observation.
- Nothing is promoted: the agenda's promotion gates on failure, unknown and
  certificate objects remain unsatisfied.
