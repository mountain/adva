# 0189 — 核与符号未展开壳：分配律是可检验的恒等式，而截断破坏的是可识别性

Status: bounded exact experiment, research-only. Evidence:
`experiments/aeg_core_shell_symbolic/evidence.json` (contract and checker beside it).
The shell form was fixed to a **symbolically unexpanded expression** by Mingli Yuan
before this ran. The terminology this implements is registered in
[`docs/terminology/aeg-core-shell-notation-v0.json`](../terminology/aeg-core-shell-notation-v0.json),
escorted by [note 0188](0188-aeg-core-shell-notation-registered-as-a-target.md).

## 0. 这一步做了什么

登记记号之后的第一步：在声明的、有限的一段有理函数片断上实现**核 + 符号未展开壳**，
并把分配律做成**可检验的恒等式传输**——两条重写路径必须产出**相等的核与相等的壳**，
而不是"在 epsilon 内接近"。全程精确：有理函数以多项式对表示，相等性用**交叉相乘是否为零
多项式**判定；另有一条独立的抽样点证书，在声明点上做**精确有理相等**。没有浮点。

载体是三层的：**核**（精确）、**壳**（未展开表达式树 + 它的精确指称 + 冻结理由）、
以及把两者绑定的**指称**。壳在构造时就强制"树必须精确指称它所携带的值"。

## 1. 结果：五条被检验的陈述

1. **射影对求逆=换位**，两次求逆回到同一个值；`A·(B+C)^{-1}` 的两条路径**精确相等**，
   交叉相乘判定，并且在 5 个声明抽样点上**逐点精确相等**。
2. **核 + 壳 = 整式**：在每个声明预算下精确成立；预算耗尽时第二个分母项被**冻结**为壳，
   带上理由与指称，判定为 `UnknownWithRetainedShell`，**而不是被舍入成一个值**。
3. **同一次截断不破坏分配律。** 这是对提案一处读法的**反证**：对"同一个"逆做一次线性化，
   它仍然只是一个值，而值的乘法本来就分配。所以"截断本身撕裂了分配律"在这一片断里不成立。
4. **逐支在不同点截断才破坏恒等式**，而且**只在两个外项不相等时**才发生（成员 0 的
   `A₁ = A₂ = 1` 时差值恒为 0）。差值不是一个笼统的"污染"，而是一个**被验证的恒等式**：

   ```
   branch_left − branch_right = (A₁ − A₂) · (T₁ − T₂)
   ```

   检查器直接验证这条等式（而不是在散文里断言）。两个成员上的精确差值分别是
   `11/18·x − 1/3` 与 `32/225·x³ − 62/225·x² − 34/225·x + 4/15`。
5. **截断真正破坏的是可识别性。** 截断后的壳**不再等于精确残差**；被丢掉的那一项非零
   （检查器验证了这一点），而它在乘上外因子之后，**不再能被读作分母的残差**——
   泄漏就等于"残差 × 外因子"，这一点也被精确算出而非描述。

## 2. 一条结构性代价：对决定了值，没有决定结构

两条路径**值相等**，但它们的**字面对不相等**（`[A : S]` 与 `[(A₁+A₂)S : S²]`）。
所以：**射影对判定的是值，不是结构**；要让两个载体作为**对象**（而非值）可比较，
必须先声明一条**化简规则**。这条是检查器的输出，不是推测。

## 3. 与本仓库既有物的关系

- 这一轮**没有**改动原生 Rust，也没有把任何东西送上原生边界。
- 壳的形态与 `docs/maintenance/FLOAT_APERTURES.md` 的清单对照：新的检查器被扫描器判定为
  **`exact-only`**（`binary64: 0`、`host: 0`、`drift: 0`），即**它一个开口都没有引入**——
  这是合同里写明的验收项，也是两个产物之间的一次交叉核对。
- 拒绝控制：零分母、零求逆、以及"壳的树与它的指称不符"（伪造壳）三者都被拒绝。

## 4. 本轮记下的四处错误

1. **系数与指数互换**（真 bug）：`Poly.__add__`/`__mul__` 里传了 `list(out.items())`，而
   `items()` 给的是 `(指数, 系数)`、构造函数读的是 `(系数, 指数)`——于是 `1 × 1` 变成空多项式，
   表现为"零分母被拒绝"。它是在跑通前第一次运行时暴露的，暴露的形式是**一个假的基础错误**，
   而不是一个错的数。
2. **合同数据与我的本意不符**：family 第 0 条的 `C` 我编码成了 `x⁻¹ + 1`，本意是 `x − 1`。
   数据自洽（合同写明是 `[系数, 指数]`），但与我要说的不是一回事。在任何证据落盘**之前**已改正，
   并在合同的 `family_note` 里记下这次更正。
3. **第一版检查器整篇重写而非打补丁**：里面有死代码、`or True` 之类的空断言、以及把符号层与
   值层混用（在值对象上调 `.value()`）。这类东西留着就会把"检查通过"变成噪声。
4. **发现措辞写绝对了**：我原本写"逐支截断会破坏恒等式"，而实测**只在两个外项不相等时**成立。
   已按成员分别记录，并把 `outer_terms_are_equal` 一并写进证据。

## 5. 这一步不成立什么

- 只在一个**单变量有理函数片断**内成立。多变量、以及"除法下理想失效"那一层，**未触及**。
- **没有**决定核的次数/理想预算，也**没有**决定终局坍缩条件的有限形式。
- **没有**把任何开口关掉：`FLOAT_APERTURES.md` 里的开口全部照旧。这一轮证明的是**另一种载体
  可以不带那些开口**，不是在既有实验上修好了它们。
- **不**主张提案其余部分（Posit 位分配、对 1.0 的对数对称、信息论调度）在本仓库成立。
- 对提案的更正只到"哪一处读法过强"为止；**不**主张提案的整体方向错。

## 7. 后继：化简规则（对的典范化），以及它为什么必须显式声明

§2 记下的缺口是：两条路径**值相等、字面对不等**。苑明理决定"化简规则"要补上，并且**壳参与**。
于是按本仓库的后继合同惯例推进：v0 合同与证据**原封不动**，新增
`contract-v1.json`（以摘要指认 v0 与 v0 的证据），把典范化写进范围。

### 7.1 规则本身

**典范形 = 用分子分母的精确最大公因式约分，然后把分母首一化。** `Q[x]` 上这是精确且便宜的
（欧几里得算法），没有近似、没有公差。规则是**显式声明的一步**，不是 `Shell` 在构造时偷偷做的
（见 §8 第 1 条）。

缺口就此闭合，而且是**字面**闭合：

| 成员 | 两条路径先前的代表元 | 典范形 |
|---|---|---|
| 0 | `2/(2x)` 与 `4x/(4x^2)` | 都是 `1/(1x)` |
| 2 | `(x²+x+2)/(2x+1)` 与 `(2x³+3x²+5x+2)/(4x²+4x+1)` | 都是 `(1/2x²+1/2x+1)/(1x+1/2)` |

并且逐位检验：典范化**保值**、**幂等**，而且**典范形是值相等的完全不变式**（两个方向都验了：
字面相等 ⟺ 交叉相乘相等）。

### 7.2 壳参与：两个声明的相等层面

"壳参与"落成两级，而不是一句口号：

- **内容相等**：核的典范形相等 ∧ 壳的**指称典范形**相等；
- **对象相等**：再加上壳的**树**、**理由**、**预算**。

实测结果是**双向**的，所以这条发现不是修辞：

- 两条路径"以不同理由冻结了同一内容"时：**内容相等 = True，对象相等 = False**；
- 而三者（树、理由、预算）都一致时：**对象相等 = True**。

所以**来源是负载的**：如果为了让两条路径"相等"而把来源丢掉，两个真正不同的冻结过程就会被
判成同一个对象——这正是 v1 合同里那三个案例要分开量的东西。**设计的后果**也如实记下：
按这个定义，**对象相等会区分过程**；哪一级才是真载体该采用的，本轮**没有**裁定，而是把两级
都声明出来、都测量出来。

### 7.3 后继的自我防护

后继运行时会**按摘要核验 v0 合同与 v0 证据**；另有一个控制：把 v0 合同改一个字节，后继就
**拒绝**而不是照跑。同时 v0 范围**仍可从它自己的合同字节级复现**（这是冻结记录的意义）。

## 8. 本轮（§7）记下的错误

1. **两次把 v0 的可复现性弄坏，两次都是"悄悄改"**：第一次是 `run()` 无条件输出新段，于是
   用 v0 合同重跑会产出 v1 内容；第二次是我把典范化放进 `Shell` 的构造里，**把 v0 的断言数与
   多项式乘法数也一起抬高了**（351→381、478→512），并且我还顺手改了 v0 那条 finding 的措辞
   （未门控）。两处都修好了：**范围由合同版本声明**，**典范化改为按需调用的显式步骤**，
   措辞按范围门控。这三件事说明：冻结记录是"合同 + 证据"这一对，**任何共享代码里的副作用都会
   穿透它**。
2. **补丁工具自身两次出错**：一次是三引号里嵌三引号（语法错，未写入，无影响）；一次是我的
   重缩进辅助函数把文件缩进搞坏（`IndentationError`）。处置是**从 git 恢复已知good版本再一次性
   重打**，而不是在坏文件上继续修。恢复过程中旧版检查器不认识 `--contract`，把它当位置参数，
   于是**写出了一个字面名为 `--contract` 的杂散文件**——已删除。
3. **`Poly` 在上一轮重写时丢了 `degree()` 与 `scale()`**，被 `canonical()` 第一次调用以
   `AttributeError` 立刻暴露（不是被一个错数掩盖）。这一族的错误本轮已是第三例。

## 9. §7 不成立什么

- 只在**单变量**内成立。多变量需要 gcd 算法与单项式序，**未决**。
- **没有**裁定"对象相等"还是"内容相等"才是真载体该采用的那一级；两级都被声明、被测量。
- **没有**决定核的次数/理想预算，**没有**决定终局坍缩条件的有限形式，**没有**动原生边界。
- **没有**改写 v0 的任何结论：同一次截断仍不破坏恒等式；逐支截断仍需"外项不相等"才会破坏；
  截断破坏的仍是可识别性。
- `FLOAT_APERTURES.md` 里的开口**一个都没关闭**。
