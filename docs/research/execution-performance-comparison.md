# Rust 直接执行、自编译和第一映射残余的执行成本

日期：2026-09-16。基线提交：`edec5df8d39094d36448c4601fb4f2e499d7fb26`。

## 结论

**当前自编译没有带来目标代码或执行步骤的优化；第一映射残余显著降低了
额外解释层的成本，与 Rust 直接执行同一小程序的成本接近。**

这里还没有两套完整 ADVA 实现可供比较。已完成的自编译器是结构化 v1
有限子集的源到指令编译器，其输出仍由 Rust 数据机执行。其外部种子编译器
是 Python；它不是 Rust PSC0 编译器的替代实现，也不是第二映射生成的编译器。
第一映射的动态残余属于另一个冻结的 v0 实验。通用 `mix`、第二和第三映射
仍然未完成。

## 同条件计时

本次使用 release 构建、同一 Rust 执行引擎、固定 CPU 0，保留全部原生
准入检查、轨迹、逐步状态摘要和报告大小检查。主机为 Intel Xeon Platinum
8259CL，编译器为 `rustc 1.97.1`。计时排除启动进程、读取/解析输入文件、
写出文件、独立重放和外部结构检查；它是现有 checked run API 的成本，
不等于整个命令行工作流的耗时，也不等于裸指令分派成本。

每个案例先执行一次并通过完整原生重放，再交错测量。普通案例取九批样本，
每批 32、64 或 128 次；两次自编译各取三个单次样本。下面的微秒数是
**各案例时间中位数的中位数**；加速比另取逐案例比值的中位数。

| 动态 v0 程序：12 个正常返回案例 | 执行步数 | 耗时（微秒/次） |
| --- | ---: | ---: |
| Rust 数据机直接执行原来的三条指令 | 3 | 26.03 |
| 第一映射生成的动态残余，由同一 Rust 数据机执行 | 2 | 23.64 |
| Adva 子集解释器解释原程序，解释器自身由 Rust 数据机执行 | 41–50 | 358.68 |

解释路径/残余路径的逐案例时间比中位数为 **14.99 倍**，范围 12.74–17.27。
直接执行/残余执行的比值中位数为 **1.067 倍**，范围 0.982–1.316，
有一个案例的残余略慢。这组小差异和样本波动不足以支持普遍的性能优势。
残余减少一条冗余输入指令是真实的代码变化；约十五倍的主要收益来自
去掉额外解释层，不能记到“自编译比 Rust 更快”的名下。

另有四个拒绝案例。Rust 直接执行、残余、解释器的对应时间分别为
23.62、21.45、338.41 微秒，拒绝状态全部一致。它们与正常返回案例分开统计。
此观察只要求返回/拒绝状态和精确返回数据一致；没有要求不同路径的拒绝文案、
完整状态或历史相等。

## 自编译与生成程序

| 编译器执行自身源代码 | 步数 | 单次时间中位数 | 三个样本范围 |
| --- | ---: | ---: | ---: |
| C1：外部种子生成的编译器 | 34,135 | 22.215 秒 | 19.900–22.631 秒 |
| C2：C1 自编译生成的编译器 | 34,135 | 22.823 秒 | 20.168–23.145 秒 |

`C1 = C2 = C3` 的规范目标字节完全相同。本次 C1/C2 执行自身源代码的
完整轨迹摘要也一致。C2 时间中位数约高 2.7%，两组范围重叠；相同代码与
相同轨迹不支持自编译阶段产生了优化或退化的解释。

十个既有测试程序覆盖常量、精确大整数、分支、循环、嵌套控制、数据字段、
整数溢出拒绝和负索引拒绝。每个程序的种子、C1、C2 目标字节都相同，
结构对应检查通过，C1/C2 产物的新执行轨迹摘要也相同。例如五次循环的
两组中位数是 94.63/95.27 微秒；嵌套控制是 125.96/126.12 微秒。
其余样本也没有目标指令差异，不能用微秒波动声称某个编译阶段更高效。

v0 动态编译步骤另行计时：八个程序的编译时间中位数为 **267.59 微秒**。
该值排除了宿主对生成数据的解码、装载和外部检查，不能据此承诺端到端
回本次数。表中的残余执行时间也不包含这笔一次性编译成本。
