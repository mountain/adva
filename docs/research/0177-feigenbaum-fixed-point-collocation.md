## 1. 这一步做了什么

上一轮的 12 位小数来自**加速过的序列**，所以那是对来源的**标定**而不是别的东西。这一步换一条路：直接解 **Feigenbaum–Cvitanović 不动点**——设 `g(x) = G(x²)`、`G(0) = 1`，解

```
G(y) = A · G( (G(y/A²))² ),      A = 1/G(1)
```

也就是 `g(x) = −α·g(g(x/α))`，其中 `α = −1/g(1)`；`G` 截断在声明次数 `N`，用 **Newton**（有限差分 Jacobian）求解，`α = −1/g(1)` 直接读出。`δ` 取**线性化算子**的主特征值（幂迭代），而线性化必须限制在**保持 `g(0)=1` 的归一化子空间**上。

**没有任何外推或加速**；报出的每个数都来自 70 位 `Decimal`，二进制浮点不参与任何报值。

最大声明次数处（N = 32）：

- **δ = `4.66920160910299067185320382046381037`** → 与已发布值一致 **31 个字符（30 位小数）**
- **α = `2.50290787509589282228390287321795506`** → 同样 **31 个字符**
- 截断之外的最大残差 `8.24e-33`；Newton 在每个次数上都收敛（残差 < 1e-40）

**内部关系检查**：`g(1)·α = −1`（即 `g(1) = −1/α`），且 `1/α` 与已记录的 A306963 前导位逐字符比对通过。前三项系数：`a₁ = −1.527632997036301…`、`a₂ = 0.10481519478730…`、`a₃ = 0.02670567052519…`。

## 3. 一个控制：虚假的主特征值

若用**未归一化**的算子（即 `T`，它不保持 `g(0)=1`）做线性化，幂迭代给出的主特征值是 **`6.2645478312170374251099074`** ——不是 δ。这不是旁枝末节：**这正是我这一轮第一次做错的地方**，当时把"全系数方向"都拿来扰动，于是拿到 6.2645 而不是 4.6692，还一度以为 δ 不该这么小。修法是把线性化限制在归一化子空间；而这个错版本现在被**保留为控制**，用来证明"取主特征值"这一步不是随手可换的。

## 4. 这一步确立什么、不确立什么

**确立**：在这个仓库里，不动点可以被直接解出，并且**在没有加速器的情况下**给出 δ 与 α 的**前 30 位小数**；位数随截断次数与残差一起自然增长；`g(1) = −1/α` 与倒数序列都通过比对。

**不确立**（**这一段比上一段重要**）：

- **不是严格计算**。截断之外的残差是**数值指标，不是被证明的误差包围**。要把它变成严格的位数，需要区间/球算术加上 Newton–Kantorovich 型的界——**那是下一步，没有做**。
- 一致位数**之后**的数字不主张；比对目标仍是一个来源（OEIS，字节未入库，只记摘要）。
- 不主张两个常数的**代数/无理性质**。
- 不主张算子**完整谱**；只报被取用的那个主特征值，以及那个作为控制的虚假值。
- 无度量、Arakelov、Monge–Ampère、镜像或 Calabi–Yau 内容；无原生 witness、无准入、无 Seal。

## 5. 三个过程错误，留在记录里

1. **`compose` 丢掉了常数项**：内层级数常数项非零时，正确的合成是 `F(c + H)`，我最初写成 `F(H)`。后果不是崩溃而是**解出了另一个不动点**：`a₁ = −1.451212…`、`α = 2.902425…`，而且它**自己的方程残差小到 1e-59**——看起来完全收敛。暴露它的唯一途径是与已发布 α 的第 10 位比较。这是这一轮最值得留下的一课：**自洽的残差不能代替外部比对**。
2. **符号约定**：`g(x) = −α g(g(x/α))` 里的整体负号不能在 `y = x²` 变量中省略（偶函数看不出参数符号，但整体符号会换掉不动点）。
3. **判据写错两处**：互反关系应是 `g(1)·α = −1`（我写成 `+1`）；控制算子最初选了归一化后的版本，于是"控制"不成立（虚假值来自未归一化的算子）。两处都在提交前被断言拦下。
4. **我把已发布的前导位抄错了一位**：契约里那条 A306963 倒数值写成了 `0.399535280523134898575804686…`，而正确的是 `0.39953528052313448985758046893…`——差一位，于是 `1/α` 的比对只有 15 个字符一致。核对两份 OEIS JSON 后确认：**来源之间没有问题**（`1/A006891` 与 A306963 一致 47 个字符），错在我这一侧。修法是两件事：改正前缀，并**新增一条检查**——两个比对目标必须互相自洽（`1/α` 前缀与倒数值前缀至少 30 个字符一致），这样抄错会在运行时被抓，而不是被拿去和计算结果比较。
