## Question and source boundary

changing its question, neutral subject role, stated value-direction, common
library contract, private policy, coverage or resource allocation?

## Finite method and preservation argument

The arithmetic universe is the seven declared integers
`D = [-3,-2,-1,0,1,2,3]`, not the field F7. A fixed expanded polynomial and
its Horner presentation are evaluated exactly, preserving their separate
traces. Coefficients and intermediate bounds remain those of Research 0145.
The main coefficients are `[2,3,1]`; reuse supplies `[-1,2,3]`. The false
proposition control declares a different target constant in the parent
question before either child runs. A forged answer under the original
question instead produces `Blocked`.

The fork fixes `D_left = [-3,-2,-1]` and `D_right = [0,1,2,3]`. Each submitted
receipt is rebound to that restriction of the same parent question and
independently reconstructed with the old checker. Exact duplicate receipts
contribute evidence and historical spending once; contradictory records for
one branch are refused. All submitted protocol conflicts are considered
before an arithmetic result is admitted. A correct counterexample refutes
the parent universal claim even if the other branch has not returned.

The conditional preservation argument is elementary. For every admitted
branch, the checker establishes that its equal points and retained frontier
partition its assigned atoms. For a missing branch, its entire assigned
domain is retained. Since the original branch domains form a fixed disjoint
partition, their union preserves the parent atoms. Consequently, absent a
valid counterexample, a merged finite equality claim requires all seven
atoms to have checked equality; receipt count or apparent local completion
cannot supply missing coverage. The argument assumes the stated checker's
correctness and the fixed partition; the calibration is not a machine proof
of this Python implementation for arbitrary inputs.

Order independence concerns only the normalized evidence judgment and
frontier. Arrival order, separate traces and audit costs remain history.
`merge` is not an inverse that erases `split`, and no unrestricted
associativity or conflict-resolution theorem is claimed.

## Resources and private boundary

Each new fixture explicitly grants 256 units. The fork costs one unit; the
normal left and right allocations are `5+64=69` and `7+64=71`, with 64
reserved for merge auditing. Unallocated funds are frozen. In the partial
case the smaller right allocation is declared in that case's root, not
silently imposed on an already-running branch. These are new calibration
budgets, not a refill of Research 0145's historical accounts.

A missing receipt leaves its entire allocation reserved and its actual
spending unknown. Unused child allocations are not refunded or reassigned.
Replaying a receipt does not redo its historical work but does incur new
checking and serialization costs. Receipt hashes bind bytes; they do not
authenticate a person, implement atomic accounting, or prevent a second
process from reusing a ledger. A production distributed service needs an
explicit persistence and authorization boundary before claiming those
properties.

The standalone replay is a separately budgeted, read-only reconstruction of
the immutable input snapshot. Its audit cost is included in the study's
global ceiling; it does not mutate the original checkpoint, refund its
accounts or constitute a second funded task action. This distinction is
essential while the reference protocol has no persistent commit service.

The CLI has no network or publishing operation. It preserves and checks the
declared private policy and writes a new local output without overwriting an
existing file. The current private GitHub workflow supplies the repository
access boundary. Policy fields and hashes are not ACLs, encryption,
anonymization or permission to disclose. Publishing the repository is not a
future obligation imposed by this protocol.

## Proposed word and executable interface

`merge(root, receipts) -> checkpoint` returns one of:

- `FiniteMergeVerified`: all declared atoms have independently checked
  equality; only an external merge checkpoint is admitted.
- `Refuted`: a valid, correctly scoped exact counterexample is retained.
- `Unknown`: missing or unfinished evidence leaves an explicit frontier.
- `Blocked`: submitted evidence or protocol commitments fail validation;
  the original task and submitted material remain available for correction.

The name has a concrete role, versioned input/output, admission and refusal
conditions, retained witnesses, an expansion/replay command, and residuals.
It is implemented only as a bounded external reference protocol. It adds no
Rust builtin and does not establish universal grammar, native free, M6
fillers, guarded multiplication-to-one or fulfilled human agreement. Zero
polynomial values remain legal exact observations without inversion.

From this branch, reproduce into a fresh output directory:

```sh
timeout 5s python3 experiments/private_merge/calibration.py --contract docs/research/0146-private-merge-contract.json --output-dir /tmp/adva-0146-new
timeout 5s python3 experiments/private_merge/merge.py --root /tmp/adva-0146-new/main-root.json --receipts /tmp/adva-0146-new/main-receipts.json --output /tmp/adva-0146-replay.json
```

Both output locations must be new. The standalone call uses the same
checked merge implementation as calibration. Resource counters are logical
units; measured host time and memory are reported separately. Neither file
size nor logical fuel is reported as peak RAM. There is no search and no
claim of speedup or increased expressive power.

## Results and handoff

One frozen calibration and one standalone CLI replay completed on
2026-09-06. All 14 expected results and both semantic/history projections
matched. There were no execution repair replays and no native invocations.

| Retained controls | Result |
| --- | --- |
| Main, exact duplicate, reversed arrival, new coefficients | 4 `FiniteMergeVerified` |
| Missing right branch, right branch with partial work | 2 `Unknown` |
| Conflicting duplicate, purpose drift, subject drift, privacy downgrade, copied parent fuel, forged trace, erased frontier | 7 `Blocked` |
| Parent explicitly declares the unequal target | 1 `Refuted`, at `x=-3`, source 10 versus target 11 |

The main merges checked points `[-3,-2,-1]` and `[0,1,2,3]`. Its historical
fork and unique child cost is 17 units; current merge checking and saving
costs 30. A duplicate costs 32 current audit units while historical cost
stays 17. Reversed arrival changes the retained arrival history, not the
semantic projection. The missing-right case retains all four right atoms
and **71 units of unreported allocation**. The partial-right case retains
`[0]`, `[1]`, `[2,3]`; no pending atom is hidden by local completion. The
counterexample still retains the failed atom and the unreceived right grant.

The calibration charges 284 physical logical units, including the fixture
construction, all audits and three experiment checkpoint writes. The
standalone read-only CLI reconstruction charges another 30, for **314 of
2000**. Controls reuse the originally constructed main receipts instead of
recreating their historical cost. Root ledgers in different control views
are not cumulative live task executions and must not be summed as such.
All receipts are constructed locally; this is not a distributed deployment.

Measured calibration phases are construction 4.793 ms, checking 5.743 ms,
and serialization 2.058 ms. Fresh-instance reuse costs 1.099 ms and overlaps
construction/checking rather than adding another independent phase. The
outer supervisor measures 53.579 ms for calibration and 39.239 ms for the
standalone CLI, **92.818 ms combined**, including interpreter startup and
output saving. The maximum measured child RSS is **13,356 KiB (13.043
MiB)** across the two process trees. Calibration's earlier in-process RSS
sample is 12,972 KiB; it is a different measurement time and scope. Each
process has a five-second wall/CPU bound and a 256 MiB address-space cap.
Research, source authoring, review and network time are not independently
measured and are not included in the millisecond result. Logical units do
not measure all interpreter instructions or all host memory allocations.

Two issues were corrected during static review before the first execution:
the inner and outer child ledgers must bind the same delegated grant, and
the entire run contract must be pinned, rather than merely comparing some
fields with Python equality. These are implementation corrections, not new
mathematical discoveries. The source was then frozen for both invocations.

The CLI accepts this deliberately small fixed root profile and partition;
arbitrary files, purposes, larger domains, new branch versions, storage
failures and adversarial distributed execution are outside the calibrated
guarantee. Malformed bounded JSON is refused; exhausted execution or failed
checkpoint saving must never be described as a successful merge. The runtime
limits are enforced, but timeout recovery beyond the outer supervisor's
record is not a native resumable service.

The minimum useful continuation is to inspect the retained checkpoint's
remaining capability requirements against the existing native `free`
boundary, then select one missing native obligation. Changing a library
contract, accepting a new privacy scope, merging successive versions of one
branch or resolving conflicting human purposes each requires an explicit
new boundary; this CLI silently permits none of them.
