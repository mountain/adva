# 0192 — 安全穿越协议的分配与准备金：0.33/0.33/0.33 与 0.01 在这套算术里是什么

Status: bounded exact experiment, research-only. Evidence:
`experiments/traversal_allocation_and_reserve/evidence.json` (contract and checker beside it,
**75 assertions**, 0.0002 s, 一条真实的 sha256 锚点链）。协议文本是方向的原话，见 §1。

## 0. 这一轮测的是什么

方向给的设计（**最优性明确留给日后再论证**，本轮**不**论证它）：

> 每侧启动前，按照 **0.33, 0.33, 0.33**，来分配时空构的资源，留 **0.01** 做成 key 和 cert
> 的部分，然后试图执行，如果 key 和 cert 部分接不起来，就可以**安全回推**。一旦接起来，
> 我们就在**三计算的 Ω 附近压缩到下一层级**了。

本轮只测**能精确测的四件事**：分配的**闭包性**、准备金**买到了什么**、回推**是不是真的安全**、
以及**额度份额与概率质量是不是同一个量**。

## 2. 分配的闭包性：**朴素检验会骗你**

- 以**百分数**写：`33 + 33 + 33 + 1 = 100` ✓ **精确闭合**。
- 以 **binary64** 写：`0.33*3 + 0.01 == 1.0` —— **居然成立**（三处高估与准备金的低估在舍入时抵回 1.0）。
  可是它在**精确有理数**里**不成立**：偏差 `−27/2^59 ≈ −4.69e-17`，**方向是高估**（多分）。
- 同一现象在三分之一上重现：`3 * float(1/3) == 1.0` **成立**，而精确偏差是 `1/2^54 ≈ 5.55e-17`。

**结论（这条比"浮点不精确"更有用）**：**普通的闭包检验查不出这个不精确**——它靠舍入"闭合"。
所以 0.33/0.33/0.33/0.01 **必须写成有理数**，而且**不能靠 `sum == 1` 来自证**。

## 3. 不精确在**步数**上才现形，而且**先吃掉准备金**

| 预算（步） | 精确规则（份额/准备金） | 逐项舍入（份额/准备金） | 舍入吃掉准备金？ |
| ---: | --- | --- | --- |
| 100 | 33 / **1** | 33 / 1 | 否 |
| 1000 | 330 / **10** | 330 / 10 | 否 |
| 10 | 3 / **1** | 3 / **0** | **是** |
| 3 | 0 / **3** | 1 / **0** | **是** |

**准备金是最小的那一份，所以舍入先吃它**（预算 10 时它被吃成 0）。精确规则下准备金**从不低于**
声明的 1%（`floor(0.33·B)` 的余数全归准备金）。

## 4. 准备金买到了什么：**临界层级**是算出来的

声明一个"key+cert 组装与验证"的代价模型，问**1% 能买到几层**（预算 1000 → 准备金 10 步）：

| 连接代价模型 | 1% 买到 |
| --- | --- |
| 常数 1 步 | **无界**（准备金不构成深度限制，只是一个定额通行费） |
| 常数 10 步 | **无界** |
| 每层 1 步（线性） | 到**第 9 层** |
| 10 步 + 每层 1 步 | **第 0 层**——即 1% **一层也买不到** |
| 每层翻倍 | 到**第 3 层** |

**这就是"最优性待论证"里可论证的那一半**：0.01 够不够**不是**这个数字的性质，而是**连接代价增长阶**
的性质；在"10+每层1步"这种模型下，1% 的准备金**买不到任何一次连接**，协议会**一次都接不起来**。
反过来，代价不随层级增长时，1% **从不成为瓶颈**（无界），此时限制来自别处。**这两个极端都不是最优性论证**，
但它们把"待论证"变成一个**可计算的判据**。

## 5. 连接是真实的哈希链，回推是"链头不动"

- 链接用保留血统的形态：`anchor_{t+1} = sha256(anchor_t ‖ checkpoint_t)` —— **真的算，不是比喻**；
  链被逐环重算并核对。
- 在**翻倍**代价下走一遍：**第 1、2、3 层接上**（代价 2、4、8 ≤ 10 步），**第 4 层起接不上**（16 > 10）
  → **与 §4 独立算出的临界层级 3 完全一致**（两条路各算一次、互相对上）。
- **回推安全**＝失败后**链头不变、已解层级不变**（逐行核对）：失败**没有**解出任何一层。
- **但"安全"取决于准备金属于谁**（统一以**步**计，预算 100）：

  | 形态 | 失败后该侧还剩 |
  | --- | ---: |
  | 准备金**在两侧启动之前**先留出（不属于任何一侧） | **33 步（不变）** |
  | 准备金**从某一侧的份额里**扣出 | **31 步**（少了 **2 步**＝那次失败连接的实际代价） |

  也就是说：**只准备金不属于任何一侧，失败才是免费的**。

## 6. 两个量必须分开：额度份额 ≠ 概率质量

- **额度份额**填满 1：`33/100 + 33/100 + 33/100 + 1/100 = 1`（**工作量**的划分）。
- **概率质量**按层减半：接上 0/1/2/3/4 层后已解出 `1/2, 3/4, 7/8, 15/16, 31/32`，未解出 `1/2, 1/4, 1/8, 1/16, 1/32`（**空间**的划分）。
- 本轮**只测量两者之间的映射**（准备金付连接、连接推层级、层级决定质量），**不把它们当成同一个量**。

## 7. 本轮记录在案的错误（三处）

1. **预期方向搞反**：我原以为 binary64 的闭包检验会**失败**，实测**成立**（舍入抵回 1.0）。
   这个反直觉结果比原预期重要，所以它现在是 §2 的主结论。
2. **函数名与返回值错位**：`layer_mass(depth)` 实际返回的是切口之后的**剩余质量**，不是层质量。
   已改名 `remaining_mass`，并在文档串里写明——这正是本仓反复记的那类错（量不是它名字所说的量）。
3. **单位混用而精确算术不报错**：carve 比较的第一版把**步数**加到了**分数**上；`Fraction` 无量纲，
   所以**精确性没有救它**。§5 现在统一以步计并声明单位。**精确 ≠ 量纲正确**，这一条值得单列。

## 8. 与三侧政策的一处**未化解的张力**（必须说出来）

方向说"**每侧启动前**分配资源"——把三侧当**三个额度持有者**；而保留的
`TriadicObserverPolicyV0` 写着三者是**同一个程序的三个输入域赋值**，并且**明确禁止**读成
"三台独立计算机的划分"。本轮为了算分配，**把三侧当额度持有者**——这是一个**建模选择**，
我把它**记成张力**而不是悄悄采用。若三侧不能各自持有额度，那么"每侧 0.33"就得改成
**同一个程序在三个域上的三段预算**，那时 §3–§5 的数字会变（连接与回推的结构不变）。

## 8.5 浮点开口清单里的位置（**登记，不修正**）

复扫把本轮**正确**判为 `imprecision-can-decide`（该类的计数 37 → 38）：因为**有两行浮点比较
落在验收路径上**——`0.33×3 + 0.01 == 1.0` 与 `3 * float(1/3) == 1.0`。这两行是**探针**：

- 它们要测的**正是** binary64 在这件事上做什么（"朴素检验会通过"是**结论**，不是论据）；
- 而承载断言的**精确**那一侧是**偏差非零且为负**（`−27/2^59`），它不依赖任何浮点行为；
- 所以若换一个不按 IEEE-754 舍入的算术，**探针会响亮地失败**，而精确断言**仍然成立**——
  这是探针该有的样子，不是需要抹掉的开口。

同一轮里另有一处**精确算术没有拦住**的东西：**单位混用**（步数加分数，§7 第 3 条）。
两条并排记在这里：**浮点会被扫描器抓到，量纲错不会被任何东西抓到**。
