Each campaign retained five seconds per receiver, twenty seconds outer wall,
32 MiB V8 old space and the original work bounds. There was no retry after
failure or enlarged semantic case family. The three-baseline and one-stress
diagnostic plans were written before execution. A subsequent focused test
invocation added one unchanged ten-child validation campaign, plus one finite
delayed Python process as a termination control. Total local receiver work:
50 children, 89,325 receiver units and 245 comparison units. These are
engineering validation costs, not renewed semantic fuel or a rewritten frozen
execution. The focused invocation passed 22 tests, including index/reference
identity and prefix/state-DAG artifact checks.

The receiver has no child-process import or asynchronous loop; for these
ordinary archived files it performs synchronous finite parsing, bounded
structural/canonical traversal, hashes and one output write. This inspection
and the repeated receipts support finite completion on these inputs, but do
not prove any host can meet a wall-clock deadline.

## Minimal CI mitigation and refusal controls

1. Install the explicit Node 24.19.0 runtime. The prior workflow used whichever
   `node` happened to be on the runner PATH; its actual version was not logged.
2. Run the two **unchanged** crosscheck tests once, in a fresh pytest interpreter
   before the long suite. Exclude only that already executed file from the
   subsequent suite. Every former assertion still gates every Python version;
   there is no skip, optional gate, enlarged timeout, retry or warm-up campaign.
3. The scoped observer emits binary path/hash, Python/platform, wall time,
   child CPU time, context switches, output byte counts and return/timeout status
   without altering subprocess arguments or swallowing an exception. Child CPU
   usage is a process aggregate, including runtime startup, not receiver-only CPU.
4. Added controls verify that a real delayed child is killed and reaped, timeout
   and nonzero exit leave no accepted receipt and trigger no retry, and the
   observer propagates the original timeout with unchanged arguments.

This isolates the replay from prior pytest state/workload and makes a future
failure observable. It is a mitigation, not an established explanation for
the historical timeout. Timeout still fails CI; it is not converted into
`ImplementationAgreement`, an accepted skip or a semantic counterexample.

No frozen receiver, runner, original test, contract, receipt, evidence,
mathematical assertion, dependency lock or index check is changed. The JSON
record pins those protected current-tree files. Prior claims and evidence
remain historical rather than being silently overwritten.
