四个独立原生程序各有 256 个字节输出，共检查 1,024 个字节构造。
每个程序输出都严格等于 `bytes(range(256))`。每个字节的四种构造均有
五个依赖节点，且全部 256 个位置都出现相同的观察分割：

| 累积观察 | 可以区分的构造类数 |
| --- | ---: |
| 字节值 | 1 |
| 加上依赖节点数 | 1 |
| 加上操作名称计数 | 3 |
| 加上编译节点中的操作名称顺序 | 4 |

操作计数仍无法分开 `copy-add` 和 `reordered-copy`：它们都含两个
constant、一个 copy、两个 add。保留原编译节点顺序后，两者分别是：

```text
constant → copy → add → constant → add
constant → constant → copy → add → add
```

这里的顺序是现有编译产物中节点的排列；不宣称它是唯一的因果执行顺序。
所有完整的节点、输入连线、输出、历史、occurrence、graft 与证书仍保留。
不同程序内相同的节点整数编号不被识别为跨程序身份。

这份有限见证说明：在本次四种构造中，即使值、规模以及部分操作计数相同，
仍可通过进一步观察已保留的程序结构区分构造。所谓“第一个”只相对于合同
冻结的四级观察表，未证明一般最小观察器或全局忠实性。
